## NP amplitude order (SMEFT@NLO) — what this slice owns
- A user-supplied amplitude order `NP=n` lands in `myprocdef['orders']['NP']`; a squared `NP^2<=m` lands in `squared_orders`/`sqorders_types`. `do_add` does NOT count EFT insertions — it only (a) gates the squared operator (541-542), (b) mirrors orders→squared `NP^2<=2*NP` if NP not in squared_orders (609-612), (c) leaves NP-driven Born selection to diagram generation. So the *physical meaning* (NP=2 → one dim-6 insertion in the amplitude → SM² ⊕ interference ⊕ EFT² in the squared ME under SMEFT@NLO's convention; NP=1 → zero EFT amplitudes → silent σ_SM) is **eft's slice** (the NP-per-insertion convention is given as eft's premise). What I confirm here: `NP=n` with no `NP^2` constraint → 611 sets `NP^2<=2n` (warn "Order NP is not constrained as squared_orders. Using: NP^2=%d"); an explicit `NP^2==m` is rejected at 542 before any of this. The `[QCD]` bracket parse that produces `proc_type[2]` is nlo-syntax's.

## `nlo_mixed_expansion` — what it actually is (claim-3 correction)
It is an **mg5 OPTION** (options dict, NOT a run_card param), default `True` (madgraph_interface.py:3115; help `set2_nlo_mixed_expansion` 8263-8265: "deactivates mixed expansion support at NLO, goes back to MG5aMCv2 behavior"; setter 8267). Persisted to `proc_characteristics['nlo_mixed_expansion']` at export (export_fks.py:876; export_v4.py:3618/4639).
- **Generation effect (do_add):** it is a **coupling-order-expansion** control, NOT a "pentagon-loops-with-non-colored-particles" switch (that gloss is not in source). True → born squared orders set as `2*qed/2*qcd` allowing MIXED QCD+QED order combinations (562-579); False (v2.x behavior) sets fixed `orders`+`sqorders` (580-605) and skips perturbing an order not in `proc_type[2]` (637-638). At 672 True also resets `perturbation_couplings` to ALL model orders when no explicit orders given.
- **Runtime read (common_run_interface.py:1035):** the ONLY runtime consumer is the width-zeroing branch of the param-card setup — `elif self.proc_characteristics['nlo_mixed_expansion']:` (1035) zeroes widths of **all** process particles (colored AND non-colored) matching the pids; the `else` v2 branch (1039-1042) zeroes only `p.color!=1` (colored) particles. So the non-colored-particle handling the claim gestures at is a RUNTIME width side-effect, not "pentagon loop inclusion." Affects processes with non-colored resonances (VBF/VBS/single-top plausible as physics context — but that's a HYPOTHESIS gloss, source only shows the width-zeroing divergence).
- `do_add:683`: `low_mem_multicore_nlo_generation` option sets `self.ncores_for_proc_gen` (0 = old way, -1 = all cores, else nb_core).

## Cautions
- The perturbation bump (`+=1`/`+=2`) is silent when the order key is already present; a missing key under `try/except KeyError` means MG puts **no bound** on that order (line 645-655) — easy to misread as "order constrained".
- `proc_type[1]` values seen here: `'real'`, `'LOonly'`, `'all'`; `proc_type[2]` is the perturbation set (e.g. `['QCD']`, `['QCD','QED']`). The `[virt=...]`/`[real=...]` bracket *parsing* itself is the **nlo-syntax slice**.
