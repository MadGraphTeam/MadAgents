# Fresh-card writers

Two distinct writers produce a from-scratch `param_card.dat`. Both differ from `ParamCard.write()` (which re-emits an already-loaded card).

## Generic `ParamCardWriter` — `$MADGRAPH_INSTALL/models/write_param_card.py` L44
Takes a live MG5 `ModelReader` model. Used at `output` time / by interfaces holding a model object.
- Computes all dependent params via `set_parameters_and_couplings` (L75).
- `self.external` = `model['parameters'][('external',)]` — only external params get written as editable lines (L81).
- `define_not_dep_param` L104: splits dependent masses/widths into `dep_mass`/`dep_width` (written as informational comment lines) and `duplicate_mass`/`duplicate_width` (params shared across particles / lhacode mismatch, L118-145).
- `write_card` L193: sorts externals via `order_param` (DECAY block always last, else alphabetical block then lhacode, L149-181); ensures `MASS` and `DECAY` blocks always emitted (`todo_block`, L202).
- `write_param` L239:
  - Strips `mdl_` prefix from the info/name comment (L246-247).
  - **Restriction sentinel substitution** (L252-256): a value of exactly `9.999999e-1` is written as `1`; `0.000001e-99` is written as `0`. These are the "magic" values the restriction system uses to keep a parameter from being pruned.
  - `sminputs 3` (aS) gets the note "this Parameter is not used if you use a PDF set" (L260-261).
  - DECAY value `'auto'` → `DECAY <pid> auto` line (L268-269).
- `write_dep_param_block` L275: emits the `## Dependent parameters, given by model restrictions` comment block — values MG5 ignores but Pythia/external tools read (L318-323).
- `write_qnumber` L326: emits `Block QNUMBERS <pid>` for every non-SM, positive-pid particle (charge×3, spin=2S+1, color rep, antipart flag; L343-348).

Header banner: `## PARAM_CARD AUTOMATICALLY GENERATED BY MG5 FOLLOWING UFO MODEL` + the "Width set on Auto will be computed... arXiv:1402.1178" note (L47-56).

## Output-time orchestration: `create_param_card_static` — `$MADGRAPH_INSTALL/madgraph/iolibs/export_v4.py:9811`
The generic `ParamCardWriter` is invoked through `create_param_card_static(model, output_path, rule_card_path, mssm_convert, write_special)` at `output` time (instance wrapper `create_param_card` L9840 passes `mssm_convert=True`). Three steps:
1. **Cached restrict-card copy short-circuit (L9815-9821):** if the model carries `restrict_card` as a string path AND a sibling file `<modelpath>/paramcard_<restrict_name>.dat` exists, that pre-built card is `files.cp`'d to `output_path` verbatim and `ParamCardWriter` is **NOT run**. `restrict_name` = `os.path.basename(model.restrict_card)[9:-4]` — strips the leading `restrict_` (9 chars) and trailing `.dat` (4 chars), so `restrict_no_b_mass.dat` → `paramcard_no_b_mass.dat`. **No bundled model ships such a `paramcard_*.dat` in this install** (`find models/ -name 'paramcard_*.dat'` → empty, v3.7.1), so the short-circuit exists but is dormant; every bundled model falls through to `ParamCardWriter(model, output_path)` (L9823).
2. **Rule-card emission (`if rule_card_path` L9826, `write_file` call L9828):** if `rule_card_path` is set and the model has a `rule_card` object, `model.rule_card.write_file(rule_card_path)` serializes it to `Source/MODEL/param_card_rule.dat`. **This is the ONLY place the on-disk rule card is created** — no `param_card_rule.dat` ships under `models/` (confirmed `find models/ -name param_card_rule.dat` → empty); it is generated here at output. Connects to the `ParamCardRule.write_file` 4-tuple-unpack crash (param-card-validation-rule-engine.md): if a model ever populated the `<rule>`/constraint category, `output` would crash here — no bundled model does, so the crash is latent.
3. **MSSM→SLHA1 (`if mssm_convert` L9830, model name `mssm`/`mssm-*` L9833):** `make_valid_param_card(output_path, rule_card_path)` (L9837, if a rule card) then `convert_to_slha1(output_path)` (L9838). So a process dir for a model literally named `mssm`/`mssm-*` gets an SLHA1 on-disk card. **DEAD for the shipped `MSSM_SLHA2`** (L9831 `model.get('name')` returns `MSSM_SLHA2` ≠ `'mssm'`) — its fresh card is native SLHA2, lowercase block names (`Block usqmix`, `Block fralpha`), probe-confirmed. See mssm-slha2-name-gating.md.

`write_special` (L9847-9856) is `True` by default but forced `False` for loop-induced / FKS exporters (controls whether the dependent-param informational block is written).

## Per-model `$MADGRAPH_INSTALL/models/<name>/write_param_card.py`
Generated alongside the UFO (e.g. `models/sm/write_param_card.py`). Standalone — imports `parameters.all_parameters` / `particles.all_particles` directly (no ModelReader). Header `## PARAM_CARD AUTOMATICALY GENERATED BY THE UFO`. This is the script `do_treatcards` runs as a subprocess in `bin/internal/ufomodel/` to (re)generate the default card when no `restrict_default.dat`/`param_card.dat` is cached (see operative-source-chain.md, L3240). On crash MG5 overwrites it with the `sm` version and retries.

## Cautions
- The `9.999999e-1`/`0.000001e-99` sentinels are emitted as clean `1`/`0` — so a fresh card never shows the magic value, but a value of literally 1 or 0 in a restricted slot is what keeps the parameter alive. Editing it can collide with the restriction.
- Dependent-parameter lines are comments-with-values that **MG5 ignores** but downstream tools (Pythia/MadSpin) read directly — do not assume editing them changes the MG5 matrix element.
- The per-model writer is regenerated per UFO; if it is stale/broken MG5 silently substitutes the `sm` writer, which may not emit model-specific blocks correctly.
