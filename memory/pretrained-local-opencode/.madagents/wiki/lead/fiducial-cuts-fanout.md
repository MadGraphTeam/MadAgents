# Fiducial cuts — three-slice fan-out

- **parton-level LO cut definitions + enforcement** → `ma-kinematic-cuts-consultant` (full entry in pipeline-stage-map). The **cut-variable identity**: run_card "eta" = true lab-frame rapidity `rap=0.5·ln((E+pz)/(E−pz))+cm_rap` (NOT pseudorapidity — the `pm`-form is commented out), "pt" = transverse momentum `√(px²+py²)` despite the `etmin` array names + printed `Et >` label; only photon isolation uses pseudorapidity (`iso_getpseudorap`). Moot for massless cut classes, but bites a massive state via `eta_*_pdg` (a rapidity cut) and any asymmetric-beam run (`cm_rap≠0`). `../consultants/ma-kinematic-cuts-consultant/rapidity-vs-pseudorapidity-in-cuts.md`.
- **NLO cut block + IR-safety** → `ma-amcatnlo-consultant` `nlo-cut-block-and-ir-safety.md` — the `run_card_NLO.dat` cut set is NARROWER than LO **for IR-safety, not feature gap** (no `ptb`/`etab`/`drbb`/`cut_decays`/per-parton cuts): jets clustered-then-cut with `njet ∈ {nQCD, nQCD−1}`, leptons cut after photon recombination, smooth-cone Frixione iso, per-particle cuts restricted to massive non-jet/lepton/photon. **String-vs-int validation gap**: a `pt_min_pdg={'21':…}` IR-unsafe cut passes `check_validity` silently (`banner.py:5977` tests int membership against string keys) and aborts only at the Fortran backstop `setcuts.f:113/:120` (`stop 1`) at run time.
- **cut↔integration seam (where cuts bite the integrator)** → `ma-phase-space-consultant` `cut-phasespace-seam.md` — cuts gated in the **sampler** (`passcuts` at `dsample.f:181`), upstream of the ME; a cut-failed point is stored into the VEGAS grid at weight zero (`dsample.f:264-268`), NOT dropped — so cut efficiency enters the integral estimate and the grid adapts around the boundary. `CUTSDONE` caches the cut once per point. Cut-derived `smin` is NOT a tau lower bound in standard pp; RAMBO (standalone `mg5> check`) applies NO cuts. Boundary: cut *parameter values* + the *body* of `passcuts`/`cuts.f` stay kinematic-cuts'; this page owns only the integration-side seam.

## cut_decays=False — fiducial cuts silently NOT applied to decay products

**Diagnostic class** — *"two process forms with the byte-identical run_card and the (physically) identical matrix element give different σ; which is my fiducial number?"* Canonical case: Drell-Yan with `ptl`/`etal`/`drll` fiducial cuts, written two ways:
- `p p > z > l+ l-` (arrow) → the **fiducial value** σ_arrow (cuts applied to the leptons).
- `p p > z, z > l+ l-` (comma decay-chain) → a **larger, un-fiducial** σ_comma (cuts silently inert on the leptons).

The robust, always-true claim is the **direction**: σ_comma ≥ σ_arrow for the identical ME, because the comma form exempts the cut targets. The *size* of the gap is entirely cut-set- and process-dependent — do NOT carry a universal ratio. *(Example for this one DY setup with `ptl`/`etal`/`drll`: arrow 1131 pb vs comma 2840 pb, ~2.5× — measured on that cut set only; re-measure per setup, never reuse the factor.)*

**Mechanism (the load-bearing diagnosis):** the comma form writes the Z as an explicit decaying resonance → `gForceBW=1` in `decayBW.inc`. At run time the cut machinery flags every `gForceBW=1` propagator *and its daughter legs* as `from_decay`, and the run_card flag **`cut_decays` (default `False`)** then switches OFF the per-particle cuts on exactly those daughters. So the fiducial `ptl`/`etal`/`drll` cuts are silently inert on the very leptons they were written for. The arrow form has `gForceBW=0`, no leg tagged `from_decay`, cuts apply. **Fix: set `cut_decays = True`** (the comma σ collapses onto the arrow σ); equivalently use the arrow form. This is a **silent regime-wrong default** (sibling of the bwcutoff-left-at-default trap — see `offshell-bwcutoff-derivation.md`).

**Dispatch:** route the `cut_decays`/`from_decay`/`do_cuts` cut-application mechanism to whichever of **ma-bw-window-consultant** (owns the `cut_decays`-vs-BW interaction: `gForceBW=1` → `from_decay` tagging — `bw-cutdecays-interaction.md`, carries the bwcutoff-invariance discriminator) and **ma-kinematic-cuts-consultant** (owns the `setcuts.f` `do_cuts` cut-application side — `cut-decays-decay-product-exemption.md`; load-bearing `setcuts.f:202-203`, `check_decay` at `:961-1003` keying on `gForceBW(i,1).eq.1`) the sub-question hits; the seam crosses both, plus **ma-chain-decay-consultant** for "why does the comma form tag the leptons as decay products" (`decayBW-artefact.md`: the comma chain sets the Z mother `onshell=True` → `gForceBW=1`). Anchor on artifacts: `decayBW.inc` `GFORCEBW` (0 arrow / 1 comma), and σ-collapse under `cut_decays=True`.

**Wrong diagnoses to refuse (all silent-fail — confident, plausible, wrong):**
- *"the comma form factorizes production × decay / applies the NWA"* — NO: both forms are the same single full-BW s-channel-Z graph (NGRAPHS=1, JAMP(1,1)=AMP(1)). No factorization.
- *"gForceBW=1 forces a BW reweighting → σ_comma is a bwcutoff artefact"* — NO: the Z is on-shell, σ_comma is **invariant under bwcutoff** (default → a large value, unchanged). bwcutoff is inert here.
- *"different amplitudes / γ*–Z interference / extra diagrams"* — NO: identical one-graph amplitude; the generated `matrix1_orig.f` differs only in HELAS wavefunction-build order (comma builds Z from final leptons, arrow from initial quarks) — *evaluation order, not physics*. A naive `diff` showing differences is the bait.
- **Discriminators that settle it:** σ_comma invariant under bwcutoff (rules out BW-reweighting); σ_comma collapses onto σ_arrow under `cut_decays=True` — a *cut* flag can't switch off an amplitude effect (rules out factorization/diagram-difference); NGRAPHS=1 in both (no extra diagram).

**Caveat — cut_decays only bites when the decay products are cut targets.** For a 4τ chain, the default `l` multiparticle is `{e,μ}` — τ's are not in it, so `ptl`/`etal`/`drll` never restricted them and `cut_decays` is moot. The trap fires only when the decay products *are* in the cut's particle class (here leptons e/μ).
