## Recent lessons (FIFO, max 5)
- to_array-does-not-sort: to_array (@1068) appends mother numbers in stored order; only __eq__ (@2230) sorts them. Don't label to_array's key "sorted mother numbers" — cross-diagram recycle relies on deterministic stored (pdg-sorted-at-construction) order, not a sort inside to_array.
- decay-chain-ordered_for_pol-set-by-guard-not-branch: in combine_decay_chain_processes the if/elif @5510-5527 ONLY populate `chains`; `ordered_for_pol` is set by a SEPARATE if/else @5529-5541 whose guard re-checks `not chains or not chains[0]`. So don't read it as "three branches each setting the flag" — it's two chains-fillers + one flag-guard. The reordered one-each case (a's `all(fs in ids)` False) is caught by elif (b) and stays ordered_for_pol=True; the pooled comment @5530-5531 "(order of decays is reversed)" is STALE. Trigger: any control-flow claim about a per-branch flag — confirm WHERE the flag is assigned, not just which branch ran.
- iden-vs-denom-two-different-denominators: in emitted matrix.f, IDEN and DENOM are UNRELATED denominators applied at different levels. IDEN (SMATRIX@175, get_denominator_factor@4910 = spin*color_of_initial*identical_particle_factor, ALL THREE folded in — final-state 1/n! is IN IDEN not separate) averages the FULL |M|^2; DENOM (MATRIX@278) is the color-matrix common denominator (max line-denominator), NOT color averaging. A process can show DENOM=1 while its initial-color-average sits inside IDEN — derive both per process, read the emitted DATA lines, don't cache a process→value pair. Also CF is a PACKED upper-triangular 1-D array (NCOLOR*(NCOLOR+1)/2), off-diagonal entries pre-doubled, single J>=I loop — NOT a full CF(j,i) matrix (asym/loop case uses 2-D). Trigger: any "what divides matrix.f / color averaging / DENOM" claim — separate IDEN(avg) from DENOM(color common-denom).
- idpartfactor-not-idmetag: the identical-particle 1/n! symmetry factor and IdentifyMETag are DIFFERENT mechanisms, routinely conflated. Factor = `Process.identical_particle_factor()` (base_objects.py:3742, prod of factorial of FS-leg counts keyed by (id,polarization)), stored via calculate_identical_particle_factor @4668, applied as denominator by get_denominator_factor @4910 → σ∝1/2 for `p p > z z`. IdentifyMETag does CROSS-PROCESS ME dedup and merely includes identical_particle_factor as an equality field @126 (so unequal-factor processes never merge); it neither computes nor applies it. Its perms/prepare_comp_dict symmetric-treatment is a COMPARISON concern, not a symmetry-factor one. Trigger: any "symmetry factor / identical particle / 1/n!" claim tied to IdentifyMETag — separate them.
