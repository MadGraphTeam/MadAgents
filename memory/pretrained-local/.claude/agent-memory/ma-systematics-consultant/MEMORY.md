- Source = code + config files MadGraph reads (run_card flags use_syst/store_rwgt_info, reweight_card, banner initrwgt). Pretrained recall is hypothesis only.
- Runtime predictions (warning text, sigma, weight-group emission) need a probe before claiming as fact; mark unprobed predictions as hypothesis.
- Reject unmarked out-of-slice claims explicitly; answer only in-slice; hand off boundary territory by description, name owning slice only if a listed redirect.
- Keep returns to the two-section shape; cite file:line, implications 1-3 sentences.
- Fail-SOFT is the subsystem default: an unmet precondition degrades/no-ops silently (logger.info/warning or forced fallback), only an enumerable set raises (see fail-soft-vs-fail-hard). "Will X error or degrade?" → degrade unless X is in the hard list. "Why are my variation/PDF/reweight weights missing?" → suspect soft no-ops (lhapdf5/absent, pdfset-download-fail, non-proton→central, OLP≠MadLoop→LO); confirm via parton_systematics.log + emitted weightgroups, never trust that the request ran.

## Recent lessons (FIFO, max 5)
- reweight-change-process-accepts-squared-order: reweight `change process p p > t t~ QED=0 NP^2==2` IS accepted — the line routes to the tree `generate` parser (ri.py:1759-1776 `mgcmd.exec_cmd`, mgcmd=MasterCmd ri.py:107), NOT amcatnlo_interface, so the HasBorn-guarded `NP^2==N` reject (amcatnlo_interface.py:541-542) never fires. Isolates an SMEFT squared-order bin via ME ratio |M_new|²/|M_old|² (the `==2` is illustrative — the quadratic-bin order is 2×(NP-per-insertion p), model-dependent; read p per model from coupling_orders.py and derive N, don't copy the integer). GATE: only the bracket-FREE branch — a `[...]` proc is diverted to get_LO_definition_from_NLO (ri.py:1760-1771) which strips the marker → write WITHOUT NLO brackets, leave mode at LO default; second_process set forces ME regeneration (ri.py:571,810). Trigger: "can I reweight to a squared/quadratic EFT bin" → yes, tree mode.
- syscalc-block-is-deprecated: run_card sys_scalefact/sys_pdf/sys_alpsfact/sys_matchscale (banner.py:4430-4433, hidden `syscalc` RunBlock, template header "code not supported anymore" banner.py:3918) feed the RETIRED SysCalc, not modern reweighting. Modern engine reads `systematics_arguments` (banner.py:4428). sys_pdf default is "errorset" NOT empty (4433). Reveal via `update syscalc` → display_block (cri.py:6892). Trigger: any run_card systematics-param question — don't call sys_pdf the way to add PDF variations.
- label-string-lies-read-the-body: sys.py dyn=1 label is 'sum pt' (sys.py:679,761) but get_et_scale (lhe_parser.py:2858-2869) sums E·pt/sqrt(pt²+pz²)=E·sinθ=Σ E_T. Trigger: a code label/string naming a physics quantity — don't trust it, read the computed body; the LaTeX name (\sum ET, sys.py:583) was the honest one.
- weight-id-1001-is-nlo-integrator-not-systematics: systematics.py get_id defaults to a base (sys.py:795) or max+1 (793) or --start_id; get_wgt_name default is bare sequential int cid (745), NOT 1001. The scale/PDF combo lives in the <weight> TAG ATTRS (MUR/MUF/ALPSFACT/DYN_SCALE/PDF, get_wgt_tag 769-781), not the numeric id — id is just a join key. The 1001-base scheme is the NLO-integrator (amcatnlo) convention; in my slice it appears only as a hardcoded FALLBACK ri.py:1354 (rwgt_dict['1001']=orig when no existing rwgt block, Sudakov). Trigger: any "id=1001" / "ids encode scale/PDF" claim → correct both.
