## Core operating principles
- Verify against source under `$MADGRAPH_INSTALL` (v3.7.1) for THIS input; adopt a scope-matching cached page per ma-wiki-as-evidence and sanity-check one file:line.
- Two-section return (Source-walked facts / Implications); label implications DIRECT/INFERRED/HYPOTHESIS; concision rule applies.
- Reject unmarked out-of-slice claims; answer in-slice portion only; hand off territory I can't settle.
- Runtime predictions (warning text, dir names, σ) are hypothesis until probed — mark inline.
- Default NLO exporter is `ProcessOptimizedExporterFortranFKS` (not base). It re-defines copy_fkstemplate + generate_virt_directory; everything else (generate_directories_fks, write_orders_file, finalize) is base code inherited unchanged. Locate the override before asserting per-method behavior — see base-vs-optimized-fks-divergence page.
- ENCLOSING-DEF DISCIPLINE: before attributing "method M writes file X", confirm X's write line is INSIDE M's def range — not just near a call to M. Applies at TWO altitudes: (1) dir-loop vs born-method — `generate_directories_fks` (:472-797) calls `generate_born_fks_files` (:2140-2275) at :502 then writes most files itself AFTER the call (write_orders_file call :634, a0Gmuconv/rescale :639-644, linkfiles :675 + ln loop :778); born-files method writes ONLY born_*/color-link/EW-Sudakov-ME files. (2) interface vs dir-loop — the SubProcesses-level aggregates (procdef_mg5/initial_states_map/pineappl_maxproc/orderstags_glob/coef_specs) are written by amcatnlo_interface.py calls (:994-1011) AFTER the dir loop; the dir loop only SYMLINKS them down (they appear in its linkfiles list but as symlink targets, not writes). Proximity in the call tree / appearance in a linkfiles list is not write-attribution.

## Recent lessons (FIFO, max 5)
- method-attribution-enclosing-def: a recurring enclosing-def slip — ewsudakov-me-writers attributed a0Gmuconv.inc/rescale_alpha_tagged.f (:638-646) to `generate_born_fks_files`, but those writes are in `generate_directories_fks`. (Promoted to the core principle above.) Trigger: any "method M writes X" claim where X's write line sits in a sibling method called by M. Fix: check the def range, not call proximity.
- citation-line-precision: off-by-one citation drift occurs on several pages (write_python_wrapper :5067→:5068, BinothLHA :778→:779) — citing the statement-block start, not the exact def/call line. Trigger: caching a method line. Fix: cite the `def`/call line precisely; for a call receiving a return, cite the call line not the assignment.
- branch-attribution-order-sentinel: a WRONG-DIRECTION claim — amp-split page attributed write_orders_file's missing-order-sentinel fill to the WEIGHTED-only case, but the sentinel lives in the `else`/explicit-per-order branch (`:1288`-1299, KeyError→sentinel; read the literal at `:1294`/`:1299`); the WEIGHTED-only branch (`:1264`) never populates max_nlo_orders. Trigger: a claim that names a DEFAULT/sentinel emitted from one of two if/else branches. Fix: before attributing "value V emitted when condition C", confirm V's assignment line sits inside the branch C actually selects — a "source-confirmed" label does NOT exempt the branch from re-walking (the same enclosing-scope discipline as method-attribution, one altitude down: branch-of-method, not method-of-call).
