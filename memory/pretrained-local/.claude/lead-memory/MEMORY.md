## Core operating principles
- **Be patient with dispatched subagents — wait for the COMPLETE reply before acting.** *Waiting is not an action I perform; it is one I stop performing.* To wait, I **end my turn**: one short line naming what I am waiting on, and **no tool call**. The harness then hands me a `<task-notification>` the instant the agent finishes — **with its full result inside** — and I resume with the answer already in hand. This costs zero tokens and needs no machinery. So I never poll, never `sleep`, never `ScheduleWakeup` (it does not fetch results and simply fails), never re-dispatch or `SendMessage` an agent to ask whether it is done, never hunt for a status channel on an MCP server, and never `Read` an agent's `output_file` (that is its entire transcript — it would overflow my context). Nor do I fill the wait with busywork duplicating what the consultant is already doing: acting on partial output produces a worse answer than simply waiting.

## NLO SMEFT: NP convention + no squared-order isolation
When a prompt requests an EFT contribution at NLO: (1) **look up the model's NP-per-insertion `p` from `coupling_orders.py` before authoring any NP constraint** (SMEFTatNLO and SMEFTsim differ); `NP=1` when `p` is larger excludes the operator silently — pin `NP=p`. (2) **For a has-Born `[QCD]` process, never propose `NP^2==N`** — MG5 rejects squared-order `==`/`>` at NLO (`amcatnlo_interface.py:541-542`, HasBorn-guarded, NOT a `has_born` test); `[noborn=]` loop-induced bypasses it (single-run bin isolation). Only `<=` survives for `[QCD]`; isolate σ_int by antisymmetric subtraction (`NP=p [QCD]` at c=±ε). See `smeft-order-bin-isolation.md` Axis 2. (3) **Include `QED=0` for SMEFTatNLO at NLO** — unset orders default to the `default_unset_couplings` sentinel (`madgraph_interface.py:3112` — read it): FREE up to the WEIGHTED cap, NOT zeroed; `QED=0` pins the Born to QCD-only, else higher-EW-order Born diagrams contaminate.

- offshell-bwcutoff-derivation: A chain-decayed intermediate cannot reach its pole: the parent mass forbids both daughters on-shell, or a daughter is pinned above its own decay threshold. - decay-widths-lifecycle: Something in the process decays, or sits in a resonant propagator, so a total width MG5 takes verbatim from the card silently scales the rate (chain sigma ~ Gamma_partial/Gamma_total; nothing checks BR<=1). - fiducial-cuts-fanout: An acceptance window on the final state (pT / eta / dR / mass), above all when the objects being cut are DECAY PRODUCTS. Three slices. - parameter-scan-fanout: The deliverable is a curve or table over a parameter rather than a single point (a sweep), or a sequential-launch thread crash.
