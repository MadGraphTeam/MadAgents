# Operative-source chain: card → param_card.inc

The bottom of the priority chain is `do_treatcards` in `$MADGRAPH_INSTALL/madgraph/interface/madevent_interface.py` L3175.

## `do_treatcards` flow (mode in ['param','all'])
1. L3207: `self.check_param_card(Cards/param_card.dat)` — resolves Auto widths and scan tags first (see scan-and-auto-detection.md).
2. Model branch L3209-3220:
   - **MSSM-family** (`tmp_model == 'mssm'` or `startswith('mssm-')`, L3211-3212, where `tmp_model = os.path.basename(self.find_model_name())`): `convert_to_mg5card(param_card, Source/MODEL/MG5_param.dat)` then `check_valid_param_card(MG5_param.dat)`; the operative card for the inc-file becomes `Source/MODEL/MG5_param.dat` (L3218). This is the only model family that regenerates a Fortran-side param file. **CRITICAL (v3.7.1): this branch is DEAD for the shipped MSSM.** The legacy `mssm` model is retired; the shipped model is `MSSM_SLHA2`, whose `name`/basename is `MSSM_SLHA2` ≠ `'mssm'` → the **else** branch (L3219, plain `check_valid_param_card`) fires, NO MG5_param.dat is created, and the card is read as native SLHA2. Probe-confirmed — see mssm-slha2-name-gating.md.
   - **Else** L3219-3220: `check_valid_param_card(opt['param_card'])` against the model's `param_card_rule.dat` restriction rules.
3. L3223: `param_card = ParamCard(opt['param_card'])`.
4. Default-card resolution L3226-3262 (for filling missing values):
   - `bin/internal/ufomodel/restrict_default.dat` if present, else
   - `bin/internal/ufomodel/param_card.dat`, else
   - regenerated by running `write_param_card.py` in `bin/internal/ufomodel/` (subprocess, L3240); on failure falls back to copying `models/sm/write_param_card.py` and retrying (L3247-3260).
5. L3265: `param_card.write_inc_file(outfile=param_card.inc, ident_card, default, need_mp=loop_induced)`.

## Where `ident_card.dat` (the read filter) comes from: `create_ident_card` — export_v4.py L9684
`write_inc_file` reads `Cards/ident_card.dat` to decide which params reach Fortran; that file is generated at `output` by `create_ident_card` (`$MADGRAPH_INSTALL/madgraph/iolibs/export_v4.py:9684`). It writes one line per `self.params_ext` — the model's **external params only** — as `<lhablock-lower> <lhacode...> <name>` (L9688-9694). A param with an empty `name` yields `''` and is silently omitted (L9692-9693). For models with `running_elements` (running couplings) it ALSO appends synthetic scale rows `mdl__<block>__scale 0 <name>` with default 91.188 (L9700-9716; `SMINPUTS` explicitly excluded, L9706-9709) — these are the lhacode-`[0]` scale rows that `write_inc_file`'s `[0]` branch reads. **So the external/internal split that governs what a card edit can change at the matrix element is fixed at output time, in ident_card** (an internal/dependent param like SM `mass 24`/MW never gets an ident line → never read from the card → recomputed Fortran-side). Note the synthetic-scale default `91.188` differs by one digit from `write_inc_file`'s hardcoded `loop`-block fallback `91.118` (L690) — close constants, distinct code paths; do not conflate.

## `ParamCard.write_inc_file(outpath, identpath, default, need_mp)` — check_param_card.py L640
- `secure_slha2(identpath)` L643 — auto-detects whether the card needs slha1↔slha2 conversion based on which blocks `ident_card.dat` expects vs the card has (`get_missing_block` L595, `secure_slha2` L614).
- Reads `Cards/ident_card.dat`: each line is `<block> <lhaid...> <fortran_variable>` (L656-664).
- For each, looks up the value in the operative card; **missing param → default-card value with a logged warning** `information about "<block> <lhaid>" is missing using default value` (L678/684). Two *distinct* fallback branches (do not conflate): (a) lhacode `[0]` (a scale row) missing → uses `self[block].scale`, else the **default card's scale** for that block with a "scale of ... is missing" warning (L668-674); (b) whole `loop` block absent from `self` AND the default-card lookup throws → hardcoded **`91.118`** (L685-690). The 91.118 fallback is keyed on `block=='loop'`+full-block-missing, NOT on lhacode `[0]`.
- Negative-mass convention: if `mass` value for a pid is negative, the corresponding `decay` width is written with a leading `-` (L691-695). This lookup is **unguarded**: L693 does `self['mass'].get(tuple(lhaid)).value` on the OPERATIVE card (not the default card) for **every `decay <pid>` line in ident_card**. It reads `self['mass']` directly, so if the MASS block is absent, or this pid's mass line is missing from the operative card and was not default-filled into `self` (the default-fill at L678 fills the *decay* value into a local `value`, not back into `self['mass']`), this raises `KeyError` at inc-file write. A distinct KeyError site from the edit-time dependent-recompute crash (override-stages-card-to-fortran.md).
  - **Probe-confirmed (this install, v3.7.1):** on a plain-SM `output` dir (no restriction-rule file) deleting the `mass 6` line then bare `./bin/madevent treatcards param` emitted FIRST `WARNING: information about "mass [6]" is missing using default value: <MT default>.` (the L678 default-fill, populating only the local decay `value`; the filled number is the DEFAULT CARD's MASS 6 — with no restrict card cached it falls through to the raw `parameters.py` MT, which DIVERGES from `restrict_default.dat`'s MASS 6, so read it fresh, don't cache a bare literal — sm-default-param-values.md) THEN crashed `KeyError: 'id (6,) is not in mass'` (the L693 negative-mass lookup on `self['mass']`). The default-fill warning is NOT a reprieve — it fills the decay value but the very next negative-mass check still dereferences the absent mass and aborts.
  - **Decay-line discriminator (resolves the apparent contradiction with override-stages' "non-fatal" probe):** deleting a `mass <pid>` line is **fatal at inc-time** iff that pid ALSO has a `decay <pid>` line in ident_card (so L693 fires). For a pid with a mass line but NO decay line (e.g. pid 6 in `e+ e- > mu+ mu-`, where the top is not in the process and its decay is pruned from ident_card), the same deletion is **non-fatal** — write_inc_file default-fills the mass value cleanly and never reaches a negative-mass lookup for that pid. This is an INC-TIER crash (fires on every launch path, including `-f`), unlike the edit-tier dependent-recompute KeyError which is launch-path-gated.
- Emits Fortran `<var> = <value>d<exp>` lines; if `need_mp`, also `mp__<var> = <value>_16` (multi-precision, L698-699).
- Scale blocks: `input.inc` is scanned for `mdl__<block>__scale` patterns (L649); those scales written as `mdl__<block>__scale = ...` (L701-703).
- Writes to `outpath+'.tmp'`, then only `shutil.move`s over the real file if content differs (`filecmp.cmp`, L707) — avoids needless recompilation.

## Full priority chain (top→bottom, per card)
1. UFO `parameters.py` (ufo slice owns content).
2. `compute_widths` resolves `Auto` (madwidth slice owns the algorithm; detection regex is here — scan-and-auto-detection.md).
3. Restriction prunes zero-resolving params (restriction slice owns the algorithm).
4. `output` writes fresh `Cards/param_card.dat` + `param_card_default.dat`.
5. User edits to `Cards/param_card.dat`.
6. `do_treatcards` → `write_inc_file` → `param_card.inc` (this page).

## Cautions
- A param missing from the operative card is NOT an error: it silently takes the default-card value (warning logged). Edits that delete a line therefore revert to model default, not to zero.
- Only a model literally named `mssm`/`mssm-*` routes through `MG5_param.dat`; for all other models (INCLUDING the shipped `MSSM_SLHA2`) the operative card is read directly. Pretrained "MSSM uses MG5_param.dat" does NOT generalize — and does not even hold for the shipped MSSM (mssm-slha2-name-gating.md).
- The default card used to fill gaps is `restrict_default.dat` when present — i.e. the restriction's defaults, not the bare UFO defaults.
