# Config system (`madgraph_interface.py` / `madevent_interface.py`)

## Option inventory (madgraph_interface.py)
Three class dicts merged into `self.options` at startup (`set_configuration` 7359-7362).
SCOPE (read-at-coordinate): every default shown in parentheses below — bool/string/path AS WELL AS numeric — is version-registered in its dict literal. The parenthetical is orientation only; read the live value at the cited dict coordinate when it is load-bearing, never quote the literal here as current. The load-bearing, version-stable content is the KEY SPELLINGS and the routing/persistence MECHANISMS, not the default values.
- `options_configuration` (3043) — tool paths + cluster + compilers + UI. Keys incl. `pythia8_path`, `mg5amc_py8_interface_path`, `hwpp/thepeg/hepmc_path`, `madanalysis5_path`, `rivet_path`, `yoda_path`, `contur_path`, `delphes_path`, `lhapdf`/`lhapdf_py2`/`lhapdf_py3`, `fastjet`, `eMELA`, `golem`/`samurai`/`ninja`/`collier`, `pineappl`, `dmtcp`, `timeout`, `auto_update`, `cluster_type`(condor)/`cluster_queue`/`cluster_size`/`cluster_status_update`/`cluster_nb_retry`/`cluster_retry_wait`, `output_dependencies`(external), `crash_on_error`(False), `auto_convert_model`(True), `acknowledged_v3.1_syntax`(True), `heptools_install_dir`. Numeric defaults (`timeout`, `auto_update`, `cluster_*`) read fresh in the `options_configuration` dict (3043+) / template.
- `options_madgraph` (3102) — generation knobs: `group_subprocesses`(Auto), `gauge`(unitary), `complex_mass_scheme`(False), `loop_optimized_output`(True), `loop_color_flows`(False), `stdout_level`(None), `max_t_for_channel`, `max_npoint_for_channel`, `nlo_mixed_expansion`(True), `zerowidth_tchannel`(True), `default_unset_couplings`, `ignore_six_quark_processes`(False), `include_lepton_initiated_processes`(False), `low_mem_multicore_nlo_generation`(False). ### run_mode / nb_core / cluster_type semantics (verified)
`set2_run_mode` docstring (madgraph_interface 8825-8834): **0 = sequential** exec of all steps; **1 = cluster** (job scheduler, backend chosen by `cluster_type`); **2 = multi-core** on current machine [the default mode], `nb_core` controls cores (None=all) — these mode↔integer meanings are the stable API. `run_mode`/`nb_core` defaults read at `options_madevent` (3118-3122) — run_mode = the multi-core mode, nb_core = None. `cluster_type` default `'condor'` (3068). Allowed `cluster_type` values = keys of `cluster.py:from_name` (2508-2510): **condor, pbs, sge, lsf, ge, slurm, htcaas, htcaas2** — note this includes `ge`, `htcaas`, `htcaas2` beyond the commonly-listed condor/sge/slurm/lsf/pbs. Template lines all shipped commented (input/mg5_configuration.txt): `# run_mode = 2`(123), `# cluster_type = condor`(131), `# cluster_queue = madgraph`(132), `# nb_core = None`(164) → dict defaults stand. Cluster mode consumers in madevent_interface: run_mode==0 single-core path (4315,4800); ==1 cluster (4774,4795; cluster.py:88 `run_mode!=1`); ==2 multicore w/ nb_core (4776,4793,4807). set2_run_mode/set2_cluster_type reached via the config `do_set` (top-level prompt), NOT the card dialogue.

### crash_on_error — a config option (not a run_card param), set before launch (verified)
`crash_on_error` is registered in `options_configuration` (madgraph_interface 3095, default **False**) — NOT a run_card/param_card key. Setter `set2_crash_on_error` (8667): builds `['crash_on_error']+args`, `check_set`, then `format_variable(args[1], bool, ...)`; on parse-failure, if `args[1].lower()=='never'` → `'never'`, ELSE re-raise. So the accepted-value set is exactly **{True, False, 'never'}** (bool-parsing accepts true/false/1/0/t/f etc.); anything else → InvalidCmd. do_set routes it: the long-`elif` stub at 9041 is dead (`raise "handled by dedicated function"`) → dispatched via the `set2_<name>` mechanism (do_set 8950). Same-shape handler in `CommonRunCmd.do_set` (common_run_interface 3613, `elif args[0] in ['crash_on_error']`). So `set crash_on_error True` works at the mg5 AND madevent top-level prompt (like run_mode/nb_core), persisted to self.options; behavior (exit-code / continue) is entirely in the extended_cmd.py error handlers — see command-loop-machinery.md. Template `input/mg5_configuration.txt` ships NO `crash_on_error` line → dict default False stands.

### `set run_mode` inside a launch block → "invalid set command" (verified)
Inside the launch CARD dialogue you hit `AskforEditCard.do_set` (common_run_interface 5868, "edit the value of one parameter in the card") — it recognizes only card params (run_card/param_card/fo_card/PY8/shower/...). `run_mode`/`nb_core`/`cluster_type` are config options, NOT card params, and are NOT routed to `self.options` here → fall to the INVALID branch (6357-6359): `logger.warning('invalid set command %s ' % line)`. The warning literal `invalid set command` fires at common_run 6160/6182/6359 (capitalized "Invalid set command" variants at 5943/6038/6052/6066 for arg-count errors, and madgraph_interface 10365/10369 for the TOP-LEVEL config do_set's own unknown-key/arg-count warnings). Correct way to set run_mode/nb_core: the TOP-LEVEL config `set` (CommonRunCmd.do_set 3536 / MadGraphCmd.do_set 8941 → set2_run_mode) BEFORE `launch`, or mg5_configuration.txt. This is the config-store-vs-card-store seam (see below + card-dialogue-set-update.md).

## set_configuration (7354) — LOAD ORDER (verified by probe)
Recurses with `final=False` for each external file, then reads the install template LAST with `final=True`:
1. `$MADGRAPH_BASE/mg5_configuration.txt` (web only, if env set).
2. user file: legacy `~/.mg5/` else `$XDG_STATE_HOME` else `~/.config/mg5_configuration.txt`.
3. `$MADGRAPH_INSTALL/input/mg5_configuration.txt` (the shipped template) — read LAST.
Each call updates the same `self.options`. CONSEQUENCE: for a key present in the install template, the install template value WINS over the user `~/.config` file (loaded earlier, overwritten). The template's comment ("place this in ~/.mg5 to override") only holds for keys the template leaves commented-out. Probe (`display options`) logged: `load ... $HOME/.config/...` then `load ... input/mg5_configuration.txt` — confirms template second.
- Parsing loop (7393-7413, verified): for each line — if `#` anywhere, `line.split('#',1)[0]` keeps only pre-`#` text (so inline comments work AND a fully-`#`-commented key line becomes empty → `split('=')` ValueError → silently ignored → the dict default stands). `name=value` split on first `=`. `value.lower()=="none"` or `value==""` → `self.options[name]=None`. Routing (7406): names in `['mg5_path','f2py_compiler','f2py_compiler_py2','f2py_compiler_py3','lhapdf']` are NOT set directly — instead `if hasattr(self,'set2_<name>') and value:` dispatch through `set2_<name>(value.split())`; all other names go straight to `self.options[name]=value`.

## LHAPDF key trio + TWO-STAGE resolution (verified this input)
Three registered keys in `options_configuration` (3082-3085): **`lhapdf`** (default `'lhapdf-config'` — this is the ACTIVE key consumers read: `self.options['lhapdf']` at 6238/6783/6793, 9746 `opts_to_keep`), **`lhapdf_py2`** (default None), **`lhapdf_py3`** (default None). Note `lhapdf_py3`/`lhapdf_py2` are python-version-specific INPUTS; the operative value all consumers read is bare `lhapdf`.
Resolution is TWO STAGES inside `set_configuration`:
1. **File-parse loop (7395-7413):** condition (7405) is `if name not in ['mg5_path','f2py_compiler','f2py_compiler_py2','f2py_compiler_py3','lhapdf']: self.options[name]=value` ELSE `elif hasattr set2_ and value: dispatch`. NOTE `lhapdf_py2`/`lhapdf_py3` are NOT in that list → they are stored RAW (no set2_ at parse time); only bare `lhapdf` dispatches `set2_lhapdf` immediately.
2. **Reconcile loop, `final=True` ONLY (7415 `if not final: return`; block at 7518-7527):** for `lhapdf_py3`/`lhapdf_py2`, if value not in `[None,'none','None']` → `self.do_set("<key> <val> --no_save")` → dispatches `set2_lhapdf_py3`/`_py2` (both aliased to `set2_lhapdf`, 8451-8452). `set2_lhapdf` (8410): if `args[0].endswith('_py2')` → `to_do=False` (skip — deliberately drops py2 line when running py3); else validates via `call([path,'--version'])` and sets BOTH `self.options['lhapdf']=path` AND `self.options[args[0]]=path` (8439-8440). Also honors an inline `--python=X.Y` filter (8422-8430): applies only if running python matches. So a user's `lhapdf_py3 = /custom` DOES get promoted into the active `lhapdf`; the `_py3` mechanism is real and works, but via this second loop, not the parse loop.
Extra dispatch site: interactive `set lhapdf_py3 <path>` at the prompt → `do_set`→`set2_lhapdf_py3` (same handler) at 9015 `elif args[0].startswith('lhapdf')`.
INSTALL-TIME population (`advanced_install`, 6359-6362): `lhapdf6` tool → sets `self.options['lhapdf_py3']=<prefix>/lhapdf6_py3/bin/lhapdf-config`, `save options <cfg> lhapdf_py3`, then `self.options['lhapdf']=self.options['lhapdf_py3']` (in-memory). `lhapdf5` (6366-6368) → sets+saves bare `lhapdf`.

- THIS install ($MADGRAPH_INSTALL) file state: line 258 has an UNCOMMENTED bare `lhapdf = $MADGRAPH_INSTALL/HEPTools/lhapdf6_py3/bin/lhapdf-config`; the `_py2`/`_py3` lines (193-194) remain commented. ## `set` scope — CONFIG store vs CARD store (two different `do_set` in different classes)
Common confusion the slice owns. `set <opt> <val>` at the **mg5/madevent prompt** hits a config/generation-option `do_set`:
- `MadGraphCmd.do_set` (madgraph_interface 8941) and `CommonRunCmd.do_set` (common_run_interface 3536, "Set an option, which will be default for coming generations/outputs") — target `self.options`, the mg5_configuration.txt store; `CommonRunCmd.do_set` auto-persists via `do_save('options --auto')` when `args[0] in self.options_configuration` and no `--no_save`.
This is a WHOLLY separate mechanism from editing a run_card/param_card value:
- **`AskforEditCard.do_set`** (common_run_interface 5868, docstring "edit the value of one parameter in the card"; class `cmd.OneLinePathCompletion`, 4944) is the `set run_card <param> <val>` / `set param_card ...` command available ONLY inside the interactive `edit_cards` question widget. It mutates the CARD object, not `self.options`.
So `set gauge unitary` (config) and `set run_card ebeam 6500` (card, inside edit_cards) invoke different methods on different objects; only the former touches mg5_configuration.txt. Card CONTENT/validity is the owning card slice; the store-routing distinction is this slice.

## do_set (8941) — the setter dispatcher
Delegates to `set2_<name>(args[1:], log=log)` if such a method exists (8950) — the `set2_*` helpers (count via `grep -c '    def set2_'`), each owning validation + side-effects + docstring help. Generic fallback: `check_set` then `self.options[name]=value` (True/False/None eval'd). The long `elif` chain (8970+) is dead — every branch raises "now handled by a dedicated function". `post_set` (9066) persists to the user config file when appropriate.

## do_save options — the three-tier persistence logic (madgraph_interface 7824)
`do_save options [file] [--all|--auto] [key ...]` decides WHICH changed options get written:
- **partial save**: if any bare arg is itself an option name → only those keys written (to the given file if it exists, else into the default base).
- otherwise, three tiers by source dict (7861-7886):
  1. `options_configuration` keys (tool paths/cluster/compilers) — written whenever changed-from-default and not None. ALWAYS.
  2. `options_madevent` keys — written unless `--auto` given.
  3. `options_madgraph` keys (generation knobs: gauge, group_subprocesses, ...) — written ONLY with `--all`. WITHOUT `--all`, a changed madgraph key is NOT persisted; instead logs "The option %s is modified [...] but will not be written ... run 'save options --all'". `stdout_level` is always excluded.
- target file: explicit non-option arg, else `$MG5DIR/input/mg5_configuration.txt`; base template `.mg5_configuration_default.txt`. Delegates to `write_configuration`.
- CAUTION: this is why `set gauge feynman` then `save options` (no `--all`) does NOT make feynman the persistent default — only a warning is printed. The user must `save options --all`.
- madevent_interface `do_save options` (2276) is the same three-tier shape but writes to `$ME_DIR/Cards/me5_configuration.txt` (not the global template).
- `do_save model`/`do_save processes` (madgraph 7824 branches) pickle the current model / (amps, proc_defs) via `save_load_object.save_to_file`. (Round-trip counterpart `do_load` is on meta-commands-introspection.md.)

## do_display options (read side) — madevent (madevent_interface 2212) vs madgraph (3566)
`display options` in **madevent** groups keys into three labeled sections — "Run Options" (`options_madgraph`), "MadEvent Options" (`options_madevent`), "Configuration Options" (`options_configuration`) — and appends ` (user set)` to any key whose value differs from its dict default (2243-2269). The **madgraph** `do_display options` (extended_cmd base 1918 / madgraph 3566) just dumps a flat `name : value` with no grouping/user-set marker.
CAUTION: `check_display` (madgraph 971-972) UNCONDITIONALLY requires `self._curr_model`; `display options` raises "No model currently active" if no model loaded. In `bin/mg5_aMC` script mode the preloop auto-`import model sm` does NOT run (cmdloop/preloop skipped on `run_cmd('import file')`), so a script doing `display options` before any `import model` fails. (Probe-confirmed.) `_display_opts=['options','variable']` + `model_list`. (Other `display` subjects — run_name/results, variable paging — are on meta-commands-introspection.md.)
