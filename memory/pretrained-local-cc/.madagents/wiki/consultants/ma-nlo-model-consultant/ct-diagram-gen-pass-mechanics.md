# CT/loop diagram-generation pass mechanics

(v3.7.1, `$MADGRAPH_INSTALL`.) `ct-vertex-consumers` covers the per-interaction `is_*`
SELECTION inside set_Born_CT / set_LoopCT_vertices. This page is the layer underneath and
around it: (a) the EXPOSURE gate that decides whether a CT vertex is even visible to the
diagram generator, and (b) the order the three CT/loop passes run in, including a THIRD
perturbation-order filter the spine page didn't enumerate.

## (a) CT vertices are EXCLUDED from the vertex dict by default
`$MADGRAPH_INSTALL/madgraph/core/base_objects.py:983-999` `InteractionList.generate_ref_dict(useR2UV=False, useUVCT=False)`:
```python
for inter in self:
    if useR2UV or (not inter.is_UV() and not inter.is_R2() and not inter.is_UVCT()):
        inter.generate_dict_entries(ref_dict_to0, ref_dict_to1)
    if useUVCT and inter.is_UVCT():
        inter.generate_dict_entries(ref_dict_to0, ref_dict_to1)
```
The vertex-lookup dictionaries (`ref_dict_to0`/`to1`) that diagram generation walks are
built from interactions, but with BOTH flags False (the default), every UV / R2 / UVCT
interaction is **skipped**. So ordinary Born / tree / loop-line diagram generation NEVER
sees CT vertices through the standard dictionaries — CT vertices are added back only by a
deliberate flag toggle. This is the model-side gate distinct from the per-vertex `is_*`
selection: the `is_*` filters in set_Born_CT/set_LoopCT_vertices decide WHICH exposed CT
vertices to keep; this `generate_ref_dict` gate decides whether they are exposed AT ALL.

## (b) The UVCT exposure toggle (set_Born_CT) — synthetic-order + double generate
`$MADGRAPH_INSTALL/madgraph/loop/loop_base_objects.py:1468-1478` `LoopModel.actualize_dictionaries(useUVCT=False)`
rebuilds the model's `ref_dict_to0/to1` by calling
`generate_ref_dict(useR2UV=False, useUVCT=True)` (UVCT branch) or the plain default.
`set_Born_CT` (`loop_diagram_generation.py:1207`) uses it as a bracket:
1. Tags each selected UVtree interaction with synthetic order `'UVCT_SPECIAL'=1` (1238-1241).
2. `actualize_dictionaries(useUVCT=True)` (1244) — now the vertex dict ALSO contains the
   UVCT interactions (but still no R2/UV, since useR2UV stays False).
3. Sets `process['orders']['UVCT_SPECIAL']=1` (1248) and re-runs the ORDINARY diagram
   generator `super().generate_diagrams(True)` (1250-1251) over the expanded dict — Born
   diagrams come back with `UVCT_SPECIAL==0`, the genuine UVCT counterterm diagrams with
   `UVCT_SPECIAL==1` (1253-1254), and only the latter become `LoopUVCTDiagram`s (1255-1266).
4. Tears down everything: deletes the `UVCT_SPECIAL` order from process/order_hierarchy/
   coupling_orders/each interaction (1270-1275), then `actualize_dictionaries(useUVCT=False)`
   (1277) reverts the model's vertex dict to the no-CT default.

So UVtree (factorizing) counterterms are generated by running the SAME diagram machinery a
SECOND time with the vertex dictionary temporarily widened — not by a bespoke CT walker.
The `UVCT_SPECIAL` synthetic order is the mechanism that lets the generic generator pick
exactly the counterterm diagrams out of the second pass. The per-LoopUVCTDiagram
`UVCT_couplings` multiplicity counts loop_particles lists not hit by forbidden_particles
(1262-1265) — the same forbidden-particle logic as the selection page, applied at counting.

## (c) The pass ordering at generate time (loop_diagram_generation.py)
Call sites, in execution order:
- `set_Born_CT()` — 765 (UVtree CTs via the toggle above → `loop_UVCT_diagrams`).
- `filter_loop_for_perturbative_orders()` — 858 (loop-diagram order purity, below).
- `set_LoopCT_vertices()` — 881 (R2 / UVmass / UVloop attached to loop diagrams).
The R2/UVmass/UVloop pass runs AFTER the loop-diagram purity filter, so it attaches CTs
only to loop diagrams that survived the order filter.

## (d) filter_loop_for_perturbative_orders — the THIRD order filter (496-543)
`perturbation-couplings-spine` lists the import gate + the per-CT-vertex `is_perturbating`
selection. This is a THIRD, diagram-level filter that runs between the Born-CT and Loop-CT
passes and DISCARDS whole loop diagrams:
- Builds `allowedpart` = PDGs of particles that `is_perturbating(order, model)` for some
  perturbed order (502-506).
- For each loop diagram, a diagram is INVALID (525-527) if its loop-line particle types are
  not all in `allowedpart`, OR if `set(loop_orders) ∩ perturbation_couplings == {}` (i.e.
  no perturbed order builds the loop). On the first discard it logs a **WARNING** (510-513,
  528-530): *"Some loop diagrams contributing to this process are discarded because they
  are not pure (`<orders>`)-perturbation. Make sure you did not want to include them."*
- ALSO invalid (531-535) if exactly ONE particle attached to the loop is non-color-singlet
  (`color!=1`) — a tadpole-like color-inconsistent diagram is dropped silently (no warning).
- Survivors replace `self['loop_diagrams']` (539).

So a loop whose internal line mixes a perturbed and a non-perturbed sector (e.g. a QED-only
loop line in a QCD-perturbation process) is filtered out HERE, at the diagram level, with a
user-visible warning — separate from the per-CT-vertex selection on the spine page.

## Boundary / cautions
- The `generate_ref_dict` exclusion + UVCT toggle is a STATIC structural mechanism: it
  predicts WHICH interactions populate the vertex dict during each pass, not numerics.
- The `filter_loop_for_perturbative_orders` WARNING text is quoted from source
  (loop_diagram_generation.py:510-513); whether a GIVEN process triggers a discard (and thus
  the warning) is a runtime/diagram-content question — PROBE-CANDIDATE, not asserted here.
  The single-non-singlet-color drop at 531-535 is silent (no warning) — note this if a user
  asks why a loop diagram vanished without any message.
- `actualize_dictionaries` mutates the SHARED model object's dictionaries in place and
  relies on the 1277 revert; the bracket is exception-unsafe (no try/finally). If
  generate_diagrams raised mid-pass the model dict would be left UVCT-widened. Hazard
  pointer, not an observed failure. (This mutate→reuse→revert bracket is one of three
  instances of a single design; the unifying principle + the other two sites are in
  ct-generation-reuses-tree-machinery-via-revertible-mutation.)
- The per-vertex `is_*` SELECTION (which kept CTs become diagrams) is ct-vertex-consumers'
  territory; the perturbation_couplings list flow is perturbation-couplings-spine's. This
  page is only the dictionary-exposure gate + pass ordering + the diagram-level order filter.
