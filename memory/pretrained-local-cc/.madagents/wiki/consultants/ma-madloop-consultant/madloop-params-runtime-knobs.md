# MadLoopParams runtime-knob reference

The knob-by-knob reference for the runtime parameters that drive the compiled MadLoop. The init machinery that consumes these (do_initMadLoop / run_initialization / StabilityCheckDriver) is in ./madloop-init-and-stability.md; the per-point Fortran driver that they steer is in ./loop-matrix-runtime-driver.md; the Python check layer that overrides MLReductionLib per-tool is in ./loop-check-infrastructure.md. THIS page owns what each knob means + its default + what actually governs it.

## MadLoopParams.dat default card (`$MADGRAPH_INSTALL/Template/loop_material/StandAlone/Cards/MadLoopParams.dat`)
The default runtime knobs (ASCII; `#Name` then value on next line). The AUTHORITATIVE param list + defaults is the `MadLoopParam(ConfigFile)` class in `$MADGRAPH_INSTALL/madgraph/various/banner.py:6130` (the .dat is its serialization; `_ID_reduction_tool_map` at :6135). These set the semantics the sibling pages reference. Defaults verified v3.7.1:
- **`MLReductionLib`** (:6-8): reduction-library priority chain (integer IDs split on `|`). Decoding key (stable): 1=CutTools, 2=PJFry++, 3=IREGI, 4=Golem95, 5=Samurai, 6=Ninja, 7=COLLIER. Default is a Ninja-first chain (Ninja→Collier→CutTools, then QP of the last, :17-19) — read the current default at the `MLReductionLib` line in MadLoopParams.dat / its `default_setup` in banner.py `MadLoopParam` (:6130). Tools absent on the system are auto-skipped (:20-21). This is the RUNTIME default ordering — distinct from the install-time `AskLoopInstaller` order in ./loop-interface-and-reduction-libs.md.
- **`CTModeRun` = `-1`** (:69-71): mode SELECTOR (value has fixed meaning, not a tunable magnitude). -1 = exhaustive auto stability (evaluate in modes 1&2, compare `(Res1-Res2)/(2*(Res1+Res2)) < MLStabThres`; if unstable redo in QP modes 4&5; modes 1/2 = DP original/reversed propagator order, 4/5 = QP) (:56-79). The runtime consequences of -1 vs -2/-3 vs >=0 are in ./loop-matrix-runtime-driver.md (full auto needs EQ.-1 specifically).
- **`MLStabThres`** (:81-83): per-point stability threshold, used ONLY when CTModeRun<0 (:80). Read its default in MadLoopParams.dat / banner.py MadLoopParam.
- **`NRotations_DP`/`NRotations_QP`** (:87-92): extra Lorentz-rotation PS-point re-evals for the stability test, on top of the 2 loop-direction evals. Read their defaults in MadLoopParams.dat; with the shipped default the stability test does only the 2 loop-direction evals and no extra rotations (see ./loop-matrix-runtime-driver.md).
- **`ImprovePSPoint` = `2`** (:115-117): mode SELECTOR for the on-shell/momentum-conservation restoration method (2=ORIG/V.H. first, 1=PSMC, <=0=ORIG, -1=none in DP; value has fixed meaning). Drives the `improve_ps.f` runtime artifact (./loop-matrix-runtime-driver.md: restoration always QP).
- **`CTModeInit` = `1`** (:153-155): mode SELECTOR used during initialization (1=DP original order). `run_initialization` overrides to 4 (QP) for the QP init attempts (./madloop-init-and-stability.md).
- **`CheckCycle`** (:161-163): #consecutive PS points the init filters must agree on. `do_initMadLoop` nPS floor is `CheckCycle+2`. Read the default in MadLoopParams.dat.
- **`MaxAttempts`** (:164-166): max filter-rebuild restarts. Read default in MadLoopParams.dat.
- **`ZeroThres`** (:170-172): analytic-zero threshold. `run_initialization` overrides it (tighter) for the QP attempts. Read default in MadLoopParams.dat.
- **`DoubleCheckHelicityFilter` = `.TRUE.`** (:185-186): re-validates HelFilter.dat against the first runtime PS point (catches stale filters after param changes).
- **`WriteOutFilters` = `.TRUE.`** (:193-194): write HelFilter/LoopFilter to disk (off for mpi threadlock cases).
- **`UseLoopFilter` = `.FALSE.`** (:200-201): loop-helicity filtering OFF by default ("gain typically minimal"). This is why `run_initialization` drops `LoopFilter.dat` from required files by default (./madloop-init-and-stability.md).
- **`HelicityFilterLevel` = `2`** (:215-216): 0=no filter (no HelFilter.dat, all helicities computed), 1=skip analytic-zero helicities, 2=also merge CP-identical (optimized_mode only). Level 0 ⇒ HelFilter.dat not required.
- **`LoopInitStartOver`=`.FALSE.`, `HelInitStartOver`=`.FALSE.`** (:221-228): consecutive-consistency requirement; Hel default false "as it can cause problems for unstable processes".
- COLLIER knobs (:239-290): `COLLIERComputeUVpoles/IRpoles=.TRUE.` (auto-disabled inside a MC), `COLLIERRequiredAccuracy` (magnitude threshold — read default in MadLoopParams.dat/banner.py), `COLLIERUseInternalStabilityTest=.TRUE.` (cheaper than loop-direction switch but less reliable; relevant only when CTModeRun=-1), `COLLIERGlobalCache=-1` (sentinel: all loops), `COLLIERMode=1` (selector: COLI branch), `COLLIERCanOutput=.FALSE.`, `COLLIERUseCacheForPoles=.FALSE.`.
- **Per-reducer auxiliary knobs** (banner.py add_param list :6146+; .dat lines noted):
  - `IREGIMODE` (.dat:39): IREGI reduction mode SELECTOR — 0=IBP, 1=PaVe, 2=PaVe with IBP-improved stability. Read default in MadLoopParams.dat.
  - `IREGIRECY=.TRUE.`: IREGI recycling of reduction coefficients.
  - `CTLoopLibrary` (.dat:128): scalar-loop library SELECTOR for CutTools/TIR master integrals — 2=OneLOop, 3=QCDLoop. (Golem95 always uses OneLOop regardless.) Read default in MadLoopParams.dat.
  - `CTStabThres` (.dat:134): CutTools-internal stability threshold (magnitude) for switching to higher precision — distinct from the `MLStabThres` loop-direction threshold. Read default in MadLoopParams.dat.
  - `UseQPIntegrandForNinja=.TRUE.`, `UseQPIntegrandForCutTools=.TRUE.` (.dat:30): evaluate the integrand in QP when Ninja/CutTools are in their QP stability mode.
  - `OSThres` (.dat:177): on-shell threshold (magnitude) for deciding whether external-momentum invariants are on-shell; used ONLY in the Golem95 S-matrix construction. Read default in MadLoopParams.dat.
- Caution: the Ninja-first default chain means a fresh proc with NEITHER Ninja nor Collier installed silently falls through to CutTools (ID 1) — runtime works but not on the "recommended" reducer. The chain is the live runtime selection; do not assume Ninja is used just because it is the install-time recommended default. (Read the actual chain at the `MLReductionLib` line in MadLoopParams.dat.)

## Loop-induced MLReductionLib override — STANDALONE-ONLY (`$MADGRAPH_INSTALL/madgraph/loop/loop_exporters.py:261-274`)
`LoopProcessExporterFortranSA.finalize` rewrites the per-proc `Cards/MadLoopParams.dat` (and `MadLoopParams_default.dat`, :274) AFTER copying the template. When `self.has_loop_induced` is True (set :806 when any ME `LoopInduced`; init False :245):
- **`MLReductionLib` forced to a Collier-first chain** (Collier→Ninja→CutTools) — comment: "for loop-induced processes and *only* when summing over all helicity configurations (default for standalone), COLLIER is faster than Ninja" (:262-265). Read the forced value at loop_exporters.py:264.
- **`COLLIERComputeUVpoles`/`COLLIERComputeIRpoles` forced `.FALSE.`** (:271-272) — poles are zero for loop-induced anyway.

**SCOPE TRAP (probe-confirmed v3.7.1):** this override fires ONLY on the pure standalone ML5 SA exporter (`output standalone` via the loop interface). The MadEvent loop-induced path uses `LoopInducedExporterME` (:3054, extends `LoopProcessOptimizedExporterFortranSA`) whose `finalize` (:3131) does NOT call `super().finalize()` — it only sets `proc_characteristic['loop_induced']=True` + `write_global_specs`. So a MadEvent `output` of a loop-induced proc keeps the Ninja-first MadLoopParams.dat default. Probe (grounding, values as observed): `generate g g > z [noborn=QCD]; output li_probe` ⇒ generated `SubProcesses/MadLoopParams.dat` had `MLReductionLib` commented (no active override line) and `COLLIERComputeUVpoles=.TRUE.` — the override did NOT apply. Do NOT claim Collier-first for a MadEvent loop-induced proc.
(.dat format note: a value line prefixed with `!` is a COMMENT; the active value is the bare line right after `#Name`. The probe card showed only a commented value line (no active override), i.e. compiled-in default.)

**`!`-comment mechanism (dual-side, statically verified v3.7.1).** The `!`-comment convention is honored by BOTH the Python and Fortran readers, by DIFFERENT mechanisms:
- Python `MadLoopParam.read` (`banner.py:6191-6197`): a value line is adopted only when `value[0] not in ['#', '!']` (`:6195`); a `!`-prefixed value is skipped, the param keeps its `default_setup` value.
- Fortran `MadLoopParamReader` (`MadLoopParamReader.f:18-20`): the outer loop only acts on a line when `index(buff,'#').eq.1` (`:20`); a `!`-prefixed value line is silently NOT matched, so its read is skipped and the compiled-in `MadLoopParams.inc` value stands.
- The TEMPLATE card (`Cards/MadLoopParams.dat`) ships EVERY value line `!`-commented (each param's value prefixed with `!`) — it is a *default* card, not a live one. Consequence: reading the template raw into the Fortran reader would crash (`read(666,*) CTModeInit` on `!1` fails) — but that never happens, because the card is consumed only AFTER `MadLoopParam.write` (`banner.py:6200-6246`) regenerates it: `commentdefault=True` (the `_default.dat` variant) re-emits `!`-commented lines (`:6238-6239`), while a normal write emits BARE active lines (`:6241`) for the live `MadLoopParams.dat`. So "the .dat governs" means specifically the WRITTEN live card with bare values; the shipped template's commented lines mean "use the compiled-in/`default_setup` default," which for the divergent trio equals the Python `default_setup` values (read `CTModeInit`/`CTLoopLibrary`/`OSThres` in banner.py), NOT the dead `DefaultParam()` values.

**SA-half probe-ability caveat (v3.7.1):** the MadEvent half confirmed exactly (`import model loop_sm; generate g g > z [noborn=QCD]; output` ⇒ `SubProcesses/MadLoopParams.dat` had commented MLReductionLib (default chain, override absent) + `!.TRUE.` COLLIERComputeUVpoles, override did NOT apply; dirs `PV0_0_1_gg_z` (loop_matrix.f, no born_matrix.f) plus a `P0_gg_z` born-config grouping dir). The SA half, however, CANNOT be probe-confirmed via the master interface in v3.7.1: `... output standalone /path` for this loop-induced proc CRASHES with `MadGraph5Error: The analytic information wavefunction_rank has not been computed yet ... alohaModel was not specified` (`helas_call_writers.py get_loop_amp_helas_calls` → `loop_helas_objects.py:463 get_helas_call_dict` → `:515 get_analytic_info` — `compute_all_analytic_information` not invoked before export on this path). This is the MASTER-interface SA loop-induced export path, DISTINCT from the loop-interface (ML5 REPL `do_output`, loop_interface.py:430) path the Collier-first override claim is scoped to. So: (a) the SA-half override remains a SOURCE-grounded claim (`loop_exporters.py:264-265` setting the Collier-first chain under `has_loop_induced`), not probe-grounded; (b) the master-interface SA crash is a SEPARATE v3.7.1 bug, NOT a contradiction of the override trap — do not conflate them.

## Fortran runtime parser (`$MADGRAPH_INSTALL/Template/loop_material/StandAlone/SubProcesses/MadLoopParamReader.f`)
This is the RUNTIME reader of `MadLoopParams.dat` — the Fortran counterpart of the Python `MadLoopParam` class above. The `.dat` is the serialization; the Python class is what *writes* defaults; THIS subroutine is what the compiled MadLoop *reads* at runtime. `subroutine MadLoopParamReader(filename, printParam)` (:1) opens the `.dat`, loops reading `#Name`/value pairs, and validates ranges inline (e.g. `CTModeInit∈[0,6]`, `CTModeRun∈[-1,6]`, `NRotations_DP/QP∈[0,2]` — all `stop` on violation, :21-225). Recognizes the `#`-token subset of the Python param list (Python-only knobs are write/orchestration-side, not read by the Fortran runtime). `MLReductionLib` parsed by splitting the pipe-joined string on `|` into the integer array `MLReductionLib(1:7)` (:156-203).

**No silent fallback on a missing/malformed card — it HARD-STOPS.** The file-open-error handler `676` (:230-233) writes `##E00 Error:: MadLoop parameter file ... could not be found or is malformed. Please specify it.` then `stop`. So a MadLoop run with no readable `MadLoopParams.dat` aborts; it does not run on defaults.

**`DefaultParam()` (:302-343) is DEAD CODE with DIVERGENT values.** Its single call site (:239) sits AFTER the unconditional `stop` at :233, so it is unreachable (the original "let the code continue with defaults" path was disabled by inserting the `stop`). And its compiled-in defaults DIVERGE from the `.dat`/Python defaults for `CTModeInit`, `CTLoopLibrary`, and `OSThres` (read both `DefaultParam()` :302-343 and the `.dat`/banner.py to see the mismatch — e.g. DefaultParam pins CTLoopLibrary to QCDLoop where the `.dat` default is OneLOop). Because the path is dead AND the `.dat` is mandatory, these divergent values NEVER govern a real run — but do not cite `DefaultParam()` as "the runtime default": the `.dat` (hence the Python `MadLoopParam` defaults) is the only thing that governs. (statically verified; not a runtime claim)
