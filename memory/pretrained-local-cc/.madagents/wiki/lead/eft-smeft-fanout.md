# EFT / SMEFT — multi-slice fan-out

Primary owner `ma-eft-consultant`, but a SMEFT task **fans across ≥7 slices** (a single restrict-card / NP choice has silent downstream effects in restriction, ufo, param-card, coupling-order, nlo-model, model-loader). Route the *sub-question* to the owning slice.

**First routing rule — the EFT coupling-order NAME is per-model; read `coupling_orders.py` before composing any order constraint:** `NP` (SMEFTatNLO; per-insertion **+2**; real `expansion_order=2` cap) vs `DIM6`+`FCNC` (dim6top; **two disjoint** orders, flavour-conserving + flavour-changing; per-insertion **+1**; uncapped `=99`). `NP=…` is *rejected* on dim6top and `DIM6=`/`FCNC=` on SMEFTatNLO (the rejected-order valid-set message lists the model's real orders).

**Second routing rule — if the ask is for a SPECIFIC polynomial piece** (σ_SM / σ_int linear / σ_quad quadratic / inclusive sum, or any `NP^2==`/`NP^2<=` constraint), route to the dedicated playbook **`smeft-order-bin-isolation.md`** rather than answering from the bin number: the bin LABEL is convention-dependent (NP-per-insertion `p` differs per UFO; σ_quad lives at `NP^2==4` on SMEFT@NLO but `NP^2==2` on SMEFTsim; odd bins are empty under p=2) and the LO `NP^2==N`-accept vs NLO `NP^2==N`-reject asymmetry forces single-run vs multi-run subtraction. "It parsed" is parse-validity, not bin-correctness.

**Return-interpretation trap — operative default = active `restrict_*.dat` value, NOT raw `parameters.py`.** A restrict card writes external-parameter *values*, not only prunes vertices; for a SMEFTatNLO parameter the operative default is what the active restrict card sets, which routinely differs from the raw `parameters.py` default. When a ufo/param-card consultant returns a default read from `parameters.py`, treat it as raw-not-operative until reconciled against the active restrict card — the four SMEFTatNLO restrict cards (`default`/`LO`/`NLO`/`NLO_no4q`) each carry their own external-value block, and the model deliberately sets a few externals *slightly* apart (an anti-merge idiom) to stop the restriction's identical-value merge from collapsing them. Re-dispatch with the active restriction named as premise if a returned default is load-bearing.
