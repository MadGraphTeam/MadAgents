# Expensive-probe backlog

These are runtime predictions / gaps the consultants flagged but could **not** settle from source alone — each needs a full `output`/`launch`/`install` (expensive). Expensive runs wait for a go-ahead. When a task touches one of these areas and runtime confirmation is wanted, re-dispatch the **owning consultant** with `/mg-probe` and a physics-anchored expectation, then fold the confirmed fact back into that consultant's subtree.

Each consultant subtree's own page carries the full one-line description; this is the lead-side roll-up so the backlog isn't lost.

## Closed probes — resolved, now facts in the owning subtrees
Runtime/parse claims once backlogged here have been confirmed and cached in the **owning consultant's** subtree; they are no longer open and their roll-up is pruned from this lead page to keep the backlog to genuinely-open candidates. To recover a closed result, dispatch the owning consultant. (Only the still-open candidates below remain lead-tracked.)
