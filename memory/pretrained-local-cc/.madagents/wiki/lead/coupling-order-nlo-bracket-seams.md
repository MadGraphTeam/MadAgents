# Coupling-order + NLO-bracket seams

- **Cuts two-layer**: kinematic-cuts owns both, but note banner.py (parse) vs setcuts.f (runtime, authoritative).
- **WEIGHTED**: coupling-order *consumes* it; the model side *computes* the per-coupling weight (ufo/base_objects).
- **split_orders**: coupling-order is the precursor; nlo-export is the consumer (`amp_split`).
- **The `[[],['QCD']]` "QCD-loop-only" gauge predicate spans two slices**: the literal exclusion set (a LoopModel whose `perturbation_couplings` is empty or exactly `['QCD']` does NOT force Feynman gauge) appears at four sites in two slices — model-load (`madgraph_interface.py:5814` post-import + `:8134` manual `set gauge`, model-loader-owned) and the `check` command (`:4423`/`:4566`, process-syntax-owned). "Why did/didn't gauge auto-switch to Feynman for this loop model" → model-loader for an `import`/`set gauge` context (`../consultants/ma-model-loader-consultant/gauge-selection-and-loopmodel-autoswitch.md`; SMEFTatNLO's `['QCD']` IS in the set → stays unitary) but process-syntax for a `check` context. Same literal, don't assume one owner.
- **Process-line parsing has THREE entry points, not one**: the main parser `extract_process` (process-syntax) is NOT the only one — `split_process_line` and `get_final_part` in `madgraph_interface.py` re-implement `@N`/`{pol}`/decay-chain stripping independently and are called by `reweight_interface.py` and MadSpin. A syntax change to the main parser does not auto-propagate. Route "how does the main `generate` line parse" → process-syntax; "how does MadSpin/reweight re-parse a process string" → madspin-interface / systematics (`../consultants/ma-process-syntax-consultant/madspin-reweight-parse-helpers.md`).
- **The `[...]` NLO bracket is parsed THREE times along the NLO add/generate path**: (1) before `extract_process`, the Switcher's `extract_process_type` (`master_interface.py`) routes `generate`/`add`/`check` to MadGraph vs MadLoop vs aMC@NLO (and forces the interface switch for loop models at import); (2) `extract_process` parses it into the ProcessDefinition; (3) `aMCatNLOInterface.do_add` parses it a third time and can **overwrite `perturbation_couplings`** — bare `[QCD]` on loop_sm with `nlo_mixed_expansion=True` (default) ends with `perturbation_couplings=['QCD','QED']`, NOT the `['QCD']` `extract_process` stored. "Which interface handles this line" → nlo-syntax `switcher-extract-process-type-predispatch.md`; "what does the bracket mean inside extract_process" → nlo-syntax `loopoption-is-the-post-remap-discriminant.md`; "what does `[QCD]` actually perturb" → `../consultants/ma-amcatnlo-consultant/do-add-nlo-order-revalidation.md`. Loop-induced `[noborn=]`/`create_loop_induced` override lands after the bracket parse — nlo-syntax `create-loop-induced-and-noborn-override.md`.
