# Process-line scope traps — "MG5 accepted it" ≠ "the amplitude is what you meant"

This page is the cross-slice dispatch playbook for the scope-trap class. Several subtrees independently carry structurally-parallel "syntax-accepted-but-wrong-scope" traps with *differing per-slice mechanisms* but a *shared diagnostic discipline*.

## When it applies
A user hands a `generate` / `add process` line (forbidden/required-propagator operators, a chain decay, or an inclusive multi-particle final state) and asks any of: "what does this compute," "is this the right process," "what's the final state," "why is my σ/result off." The dispatch trap: confirming the *syntax* is valid — MG5 ran, made an output dir, would give a σ — is **not** confirming the *amplitude scope* matches intent.

This is the **complement** of `process-verification-fanout.md` (which routes "why was my process REJECTED" — loud parse/validation/stability failures). There the failure announces itself. **Here the dominant mode is SILENT:** clean run, wrong matrix element. The single most important dispatch move is therefore: **add a topology check to the plan** — diagram count, vertex-routine grep, `leshouche.inc` IDUP, `nexternal.inc` NEXTERNAL — never accept "it ran and gave a σ" as evidence the scope is right.

## The two-axis taxonomy
- **Silent fail** — MG5 accepts, generates an output dir, would produce a σ; amplitude scope ≠ intent. Caught only by inspecting the generated ME, never by exit code. The dangerous class (single-`$`; comma-only sub-decay discard [warning present but output completes exit 0]; inclusive-vs-chain; clause mis-distribution).
- **Hard fail** — MG5 errors at parse time, no output dir. Self-announcing; route the tokenization/name-resolution behavior to process-syntax (`/= z`; misplaced paren).

## Per-trap routing (the four canonical cases)

### 1. Forbidden/required s-channel operators — `$` vs `$$` vs `/` vs `> >`  → ma-diagram-filter-consultant
**Trap: `/ X` ≠ forcing X as a resonant propagator.** The `/ X` operator forbids X *anywhere* in diagrams — it is a **diagram filter**, not a topology constructor. Proposing `p p > z z / a a > e+ e- mu+ mu-` to isolate the ZZ-mediated contribution is wrong on two counts: (a) MG5 rejects `/ a a` between intermediate and final states (restrictions go after final states); (b) even with correct placement, `/ a a` only removes photon diagrams — it leaves single-resonant Z, γ*/Z, and non-resonant topologies untouched. `/` excludes particles; it does **not** force any particle to appear as an explicit propagator. To force multiple intermediate particles as explicit resonant propagators, use the **comma syntax for sub-decays**: `p p > z z, z > e+ e-, z > mu+ mu-`. This is the canonical example of confusing a diagram filter with a topology constructor.
The **headline silent-fail: single `$` ≠ double `$$`.** Parse + storage in `madgraph_interface.py`; effect in `diagram_generation.py`:
- `$$ X` → `forbidden_s_channels` (regex `:5022`, key `:5345`): **REMOVES** the X s-channel diagram (`diagram_generation.py:742-776`).
- `$ X` → `forbidden_onsh_s_channels` (regex `:5029`, key `:5344`): **KEEPS** the diagram, marks one leg `onshell=False` (`:781-794`, semantic write at `:792-793`); only the on-shell region gets special treatment. **Silent fail** if the agent thinks `$` forbids X — the X contribution survives off-shell → a hybrid amplitude, not the X-excluded piece.
- `/ X` → `forbidden_particles` (regex `:5012`, key `:5343`): forbids X *anywhere*. LO-identical to `$$` for a single-propagator 2→2; strictly stronger at higher multiplicity / NLO (also kills t-channel, radiation X).
- `> X >` → `required_schannels` (regex `:5036`, key `:5346`): **FORCES** X as the s-channel intermediate (`a > l+ l-` "force γ"; `p p > z > l+ l-` "force Z"). Opposite of forbidding — the "I used `> z >` to isolate γ" inversion is a hard-fail-by-opposite-intent.
  - **`> X >` is "must-INCLUDE X somewhere", NOT "only-X-mediated" (exclusivity).** The seductive misread: `h > z > ta+ ta- ta+ ta-` reads as "H decays through Z's into 4τ — ZZ-mediated only," but it retains *every* H→4τ diagram with **at least one** Z propagator anywhere on its path. Under default `sm` (Y_τ≠0) that **admits Yukawa diagrams**: H→τ⁺τ⁻ via the Hττ vertex with one τ-line radiating a Z*→τ⁺τ⁻ — there IS a Z (the radiated one), so it passes `> z >`, but the H-decay vertex is Yukawa, not HZZ. Silent fail: σ only ~7–10 % above the explicit chain, within LO scale band. The explicit chain `(h > z z, z > ta+ ta-)` (both Z's declared as decay-tree intermediates) leaves no room for a Yukawa vertex. **Fingerprint:** `grep -c "FFS4_3.*GC_99.*MDL_MH" SubProcesses/P*/matrix1_orig.f` — **0** for the explicit chain (pure ZZ: only `FFV2`/`VVS1`), **nonzero** (larger for fully inclusive `h > ta+ ta- ta+ ta-` than for `> z >`) when Yukawa-Hττ contamination is present. The count also separates the two contamination forms — run the grep for the values. (Cross-ref: `offshell-bwcutoff-derivation.md` — agents reach for `> z >` precisely to *dodge* the bwcutoff issue, hitting this trap instead.) Owners: ma-diagram-filter-consultant (the `>`-filter semantics) + ma-chain-decay-consultant (the explicit-chain restriction).
- **Diagnostic (agent-actionable):** diagram count. `$ X` matches the *baseline* count (diagram kept) — that match is the tell that `$` did NOT remove X. `$$`/`/`/required give the reduced/forced count. Or grep the vertex routines in `matrix1_orig.f` (Z-vertex `FFV2_*` count = 0 ⇒ X removed).
- Pages: `../consultants/ma-diagram-filter-consultant/diagram-filter-enforcement.md` (+ `parse-filter-operators.md`, `filter-operator-visibility-matrix.md`, which carry the four-operator semantics, the `$$`-before-`$` precedence, and the diagram-count tell).
- **What the kept diagram computes under `$`** (the BW-principal-value / on-shell-peak treatment): the `onshell=False` flag feeds (a) `gForceBW=2` in `decayBW.inc` and (b) an ALOHA `P1D`-tagged propagator routine (e.g. `FFV2_5P1D_3`) that takes `BWCUTOFF` as an argument — **generation-time HELAS/ALOHA** (`helas_objects.py:1597-1600`/`:1898`, `aloha_writers.py:241`), **NOT** the `myamp.f` runtime `cut_bw` window (zero matches there). bw-window owns only the `bwcutoff` *value* the routine consumes → `../consultants/ma-bw-window-consultant/bw-gforcebw-lbw-provenance.md`. The exact peak-subtraction algebra is **aloha's** slice (`aloha_object.py:1650` DenominatorPropagator) — **INFERRED**, not separately grounded here; ship "single-`$` keeps the Z diagram as a BWCUTOFF-windowed hybrid" and stop there, or dispatch ma-aloha-consultant for the algebra. (Cross-links the `onshell` field in `decay-chain-seams.md`: single-`$` is the semantic `onshell=False` writer; `$$` is NOT.)

### 2. Chain-decay clause distribution → ma-chain-decay-consultant
A single decay clause distributes across **every** matching final-state leg of that pdg in scope. `h > z z, z > e+ e-` has two Z's and one clause → the clause is duplicated onto **both** → final state `e+ e- e+ e-` (4 electrons), not "one Z decays, one stays / decays invisibly." There is **no implicit invisible-decay default**. To give the two Z's different decays, write two clauses (`z > e+ e-, z > mu+ mu-`); when the two clauses have distinct final states, each binds exactly one Z so comma-only is unambiguous there. Mechanism: `set()` of `decay_ids` (`diagram_generation.py:1392-1395`) + per-matching-leg flag (`:1284-1299`) + Cartesian HELAS combine. Probe signature: two `Decay: z > e+ e-` log lines, `P1_h_zz_z_ll_z_ll`, IDUP=(25,-11,11,-11,11), NEXTERNAL=5. Page: `../consultants/ma-chain-decay-consultant/clause-distribution-and-topology.md`.

### 3. Chain-decay parenthesisation scoping → ma-chain-decay-consultant (+ diagram-enum warning, + process-syntax tokenization)
A sub-decay of a decay *product* must be wrapped in parens scoping it to its parent's clause: `(t > b w+, (w+ > l+ vl))` or equivalently `(t > b w+, w+ > l+ vl)` — the **outer** parens bind the scope.
- **Comma-only top-level chain** `p p > t t~, t > b w+, t~ > b~ w-, w+ > l+ vl, w- > l- vl~` → **silent-ish fail**: MG5 can't scope `w+ > l+ vl` against the W-less core `p p > t t~`, **discards** the W sub-decay (warning), leaves W as an ME external → `b b̄ W+ W-`, not `b ℓ+ν b̄ ℓ-ν̄`. Output still completes exit 0 — the warning is loud in the log but easy to miss. Scoping grammar: chain-decay `comma-parser.md`.
- The **"Decay without corresponding particle in core process found / Decay information for particle(s) … is discarded"** warning emission: diagram-enumeration `decay-chain-amplitude.md` (`diagram_generation.py:1399-1424`; only the unmatched sub-decay is removed, the core survives — never a hard error). The discarded-particle list (`w+,w+`) is cosmetic; the warning's *presence* is the diagnostic.
- **Misplaced paren** `t > (b w+, …)` (open paren after `>` instead of before the parent) → **hard fail** `InvalidCmd: No particle (b in model` (`(b` read as one token, `madgraph_interface.py:5242`; balanced-paren branch passes `:1154` first). Process-syntax `loud-parse-rejection-traps.md`.

### 4. Resonant chain vs inclusive ME — same final state, different amplitude → ma-diagram-enumeration-consultant (+ chain-decay, physics)
`p p > z z, (z>e+e-), (z>mu+mu-)` = **doubly-resonant ZZ only** (chain restricts to production-graphs × spin-correlated decays; few graphs/channel, **0** photon `FFV1` calls — a structural zero). `p p > e+ e- mu+ mu-` = the **same final-state multiset** but the full graph set (+ single-resonant Zγ*, γ*γ*, non-resonant 4ℓ; many more graphs/channel, **nonzero** `FFV1` calls) → **silent fail**, σ off by a large fraction under the default card. The seductive trap: "same final state ⇒ same process" is FALSE.
- **Fingerprint (diagnostic):** diagram count + `grep -c 'CALL FFV1' matrix1_orig.f` (FFV1 = photon-fermion vertex, `GC_2`/`GC_3`, QED order — grounded in `couplings.py`). Chain: FFV1=0 (no photon-fermion vertex — a structural zero, always) and a small N_MAX_CG; inclusive: FFV1 nonzero (many photon vertices) and a much larger N_MAX_CG — run the grep for the counts. Page: diagram-enumeration `enumeration-topology-fingerprint.md`. Chain-restriction side: chain-decay `clause-distribution-and-topology.md`.
- Physics: doubly-resonant diboson *signal* vs the inclusive 4ℓ *continuum* are different observables (standard signal-vs-continuum distinction; route to ma-physics-* if the user asks whether the difference is physical).
- The loud variant: **undecayed `p p > z z`** leaves the Z's stable, the e+e-µ+µ- final state never appears — NEXTERNAL=4 not 6.

## Dispatch discipline / return-interpretation
- **First move** on any "what does this process line compute / is this right" question: dispatch the scope-determining-operator owner (above) **and put a topology check in the plan**. Anchor the silent-fail diagnostic on the *generated artifact* (diagram count, `matrix1_orig.f` vertex routines, `leshouche.inc` IDUP, `nexternal.inc` NEXTERNAL), never on the command string alone — the string can look right and compute wrong (`$ z`, inclusive ME). The topology-fingerprint method's named home is diagram-enum `../consultants/ma-diagram-enumeration-consultant/enumeration-topology-fingerprint.md` (count + vertex-grep discrimination table); the per-case instance pages cited above sit under it.
- **Umbrella:** this page is the *scope* member of the silent-physics-wrong family — see `clean-run-not-correct-physics.md` for the family-wide "it ran is not evidence" discipline and the route-by-symptom table.
- A consultant return that says "already on my page, no drift" is a **confirmation**, not a miss — these traps are stable across v3.7.1.
- These are **easy-tier** questions whose difficulty is entirely the silent-fail recognition; don't over-fan. One scope-owner per operator + one topology check is the right depth. Reach for bw-window/aloha only if the user asks what the kept-`$`-diagram numerically computes; reach for physics only if they ask whether the scope difference is physically meaningful.
