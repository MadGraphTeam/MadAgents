- `ma-nlo-syntax-consultant` — `[QCD]`/`[QED]`/`[virt=]`/`[noborn=]`/`[real=]`/`[sqrvirt=]`/`[LOonly=]`/`[only=]` bracket parse, `LoopOption`/`HasBorn`, FD/axial gauge restriction fires at process-spec time (bare Exception). **Squared-order bypass seam:** the `NP^2==N`/`>` reject (`amcatnlo_interface.py:541-542`) is literally a `sqorders_types != '<='` test on the amcatnlo `do_add` path (NOT a `has_born`-field test) — it is *reached* only by a has-Born `[QCD]` process, because an *explicit* `[noborn=]` loop-induced process is routed by `master_interface.py:200-236` to `create_loop_induced` (`madgraph_interface.py:5357-5420`, no sqso check) *before* that line → single-run squared-order bin isolation works. Route loop-induced signal/bkg/interference isolation here (parse) + coupling-order/madloop (accept), NOT to the has-Born subtraction recipe. **Two more surfaces reject** (shared decay-chain guard `madgraph_interface.py:3301-3304` `decays_have_squared_orders`): a MadSpin decay AND a directly-typed `generate` decay-chain both reject `NP^2==N`; reweight `change process` in **tree-mode accepts** it (`reweight_interface.py:1759-1776`) but `[QCD]` there strips the marker. - `ma-madloop-consultant` — loop diagram generation, R2/UVtree/UVmass/UVloop, OPP/TIR (CutTools/IREGI bundled; Ninja/Collier recommended), `do_initMadLoop` DP→QP stability, loop-induced (`NoBornException`/`has_born:False`).
- **Reconciliation — "which EW/pentagon loops are kept" and "coupling-order expansion" are ONE mechanism, not two separate questions.** `nlo_mixed_expansion` (run_card, default **True**, `banner.py:1770`) sets the `perturbation_couplings` that MadLoop's `filter_loop_for_perturbative_orders` (`loop_diagram_generation.py:496-539`) consumes to decide which loop diagrams survive. That filter is **topology-agnostic** — no pentagon/box/leg-count predicate; it keys on coupling order alone. So a "does MadGraph include the EW/pentagon loops at NLO" question is NOT a madloop-topology question distinct from an amcatnlo coupling-order question: dispatch madloop (the filter) **and** amcatnlo/nlo-syntax (what sets `perturbation_couplings`), and read them as one decision (`amcatnlo_interface.py:672-673`, `fks_base.py:371-374`). Corollary — dropped W/Z/γ/H loops in a `[QCD]` run are `[QED]`-order and carry **no QCD IR singularity**, so discarding them is *required* (their DGLAP/soft counterterms are absent), not a bug; there are TWO warnings — an actual-drop `"(QCD)"` note (`:510-513`) vs a heuristic (`:736-739`). → `../consultants/ma-madloop-consultant/furry-and-loop-filters.md`.

**Loop-model availability seam** (`loop_qcd_qed_sm` for NLO EW, etc.) fans nlo-model + installation — and the split is a routing trap: whether a loop model is bundled/on-disk is a **shell-check** (`ls $MADGRAPH_INSTALL/models/`), and *obtaining* a non-bundled loop model is `import model <name>` (online model-DB auto-fetch), **not** an `install <name>` command (loop models are not install-tokens). Route "how do I get loop_qcd_qed_sm / which restrictions does it have" to nlo-model (`bundled-online-loop-models.md`, restriction-tag metadata `madgraph_interface.py:2895`) with the install-vs-import mechanism from installation.
