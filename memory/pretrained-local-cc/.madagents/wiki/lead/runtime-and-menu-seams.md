# Runtime + menu seams

- **`-O` / `__debug__` runtime divergence**: an installed `mg5_aMC` auto-re-execs under `python -O` (`bin/mg5_aMC:75-78`), so `__debug__==False` by DEFAULT at runtime — terse one-line errors, `history.pop`-on-InvalidCmd inactive, `@debug` a no-op, SmartQuestion swallowing widget errors, install `__debug__` gates taking the False branch, MA5-install auto-recovery only in the release run. Route "why terse / no traceback / why didn't X auto-recover" → `../consultants/ma-interface-consultant/optimize-mode-debug-divergence.md` (REPL sites) or `../consultants/ma-installation-consultant/debug-flag-release-behavior.md` (install sites). `--debug` flips it back. Third data point (systematics): the NLO nominal-weight consistency-assertion (`sys.py:1095-1101`) and the reweight `libsudpy` compile-failure branch (`ri.py:2177-2184`) hard-error under `__debug__` (the default run is the STRICTER one) but short-circuit under `-O`; a cluster subprocess inherits `-O` only when the parent had it (`cri.py:1956-1957`).
- **`'PY8' in available_module` gates downstream switch availability**: whether the `launch` switch even *offers* Rivet (and how Delphes/MA5 auto-resolve a shower) keys off the pythia8-owned boolean `'PY8' in self.available_module`, set from `pythia8_path`. "Why isn't Rivet/Delphes offered / why did it force a Pythia8 shower" is a pythia8-interface-owned precondition consumed by the downstream slice. Route the boolean's truth → pythia8-interface; the consumption gate → the owning downstream slice (`../consultants/ma-rivet-interface-consultant/rivet-suppression-gates.md`; delphes' `consistency_detector_shower` forces a shower on).
- **Python xsec roll-up does NOT re-apply mfactor**: `Combine_results.compute_values` (`sum_html.py`) sums the raw per-channel `xsec` — the ×mfactor symmetry-multiplicity is applied inside `OneResult.get('xsec')` for the refine arithmetic, but the HTML/Python total does not re-multiply. Total correctness depends on whether the representative channel's Fortran `axsec` already folds symmetry. Route "does the final σ double-count or drop symmetry factors" → numerical (`mfactor-not-in-python-total`) for the Python side, phase-space for the Fortran `axsec` side. (Open probe — see `probe-backlog.md`.)
- **ControlSwitch / launch-menu consistency-flip = chosen-value ≠ enforced-value at the menu layer**: the AskRun/AskRunNLO menu does NOT honour a selected switch verbatim — `set_switch`→`check_value` can coerce a pick to OFF (warning only) or rewrite it, and `check_consistency` mutates *other* switches (Rivet forces shower Pythia8 ON; `shower=OFF`+active Delphes forces detector OFF; `detector=Delphes`+non-Pythia shower forces shower→Pythia8). **Precedence is last-changed-wins**, not a fixed priority: whichever switch the user set *most recently* is the trigger and forces the other (`last_changed`, `extended_cmd.py:2799-2801`). **"Silent" needs qualifying** — there is genuinely NO `logger.warning`/`print` on the forced-override path (the commonly-stated "no warning is printed" is literally true), but interactively the *next* menu redraw renders the forced axis as a `chosen < replacement` arrow (`create_question`, sourced from `inconsistent_keys`), so an interactive user *does* see it; the change is only truly invisible under scripted / `launch -f` execution, where no redraw occurs and the forced value reaches `get_cardcmd` via the `answer` property with no console notice. Do NOT tell a user the flip is "completely silent" without that interactive-vs-`-f` split. Menu-internal twin of the config-value-lifecycle shape and a precondition for `downstream-card-existence-gate.md`. Route switch-coercion/consistency mechanism (announce-vs-silent, the fixpoint engine) → interface (`../consultants/ma-interface-consultant/controlswitch-widget.md`); the concrete `consistency_shower_detector`/`consistency_detector_shower` coupling rules live in launch/madevent-interface (`../consultants/ma-launch-consultant/launch-menu-switcher.md`); the availability boolean itself is pythia8-owned.
- **Downstream `--no_default` dispatch convention**: in the automated `generate_events` chain, a downstream-tool step (MA5/Delphes/PGS/Pythia/Rivet) silently skips when its card is missing/default, whereas the same command issued directly asks-or-raises. Do NOT assume a downstream step ran just because it was in the chain. Full playbook → `downstream-card-existence-gate.md` (three-condition gate path-set / card-exists / card-non-default + per-tool pointers).
- **Reasoning slices** (`ma-physics-*`, `ma-math-*`, `ma-numerics-*`) reason from their domain, not source — not part of `/mg-study`. Route standalone physics/derivation/computation there; route "what does the source do" to the owning mechanics slice.

(The "vestigial / dead-code-with-divergent-defaults" seam — present-but-unreachable code paths + compiled-in defaults that diverge — is its own playbook: `dead-code-liveness.md`, which is both the dispatch layer and the catalog of per-slice instances.)
