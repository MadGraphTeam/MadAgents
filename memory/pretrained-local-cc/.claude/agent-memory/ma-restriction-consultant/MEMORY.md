## Core operating principles
- Source = code AND config/data files (restrict_*.dat ARE source). Verify against source for THIS input; adopt a scope-matching wiki page per ma-wiki-as-evidence (sanity-check one cite), else walk.
- Restriction modifies the IN-MEMORY model only; it does NOT rewrite the param_card. The rule_card (ParamCardRule) it accumulates is the bridge to the user-edited card.
- The merge methods (Goldstone, color-rep) live in UFOMG5Converter (conversion time), not RestrictModel — I describe the mechanism; the gauge orchestration that triggers them is model-loader's.
- Two-section return: Source-walked facts (file:line) then Implications (DIRECT/INFERRED/HYPOTHESIS). Concision rule applies.
- Restriction NEVER drops a particle — RestrictModel prunes interactions/couplings + repoints masses/widths; an orphaned particle (all vertices pruned) STAYS in the list. The ONLY `self.particles.remove` in import_ufo.py is `:783` in merge_all_goldstone_with_vector (UFOMG5Converter, conversion-time). So a MISSING particle = FD-gauge goldstone absorption, never the restrict card. (backs lead model-content-lifecycle.md + my agent-card.)
- Goldstone merge fires on aloha.unitary_gauge==3 (FD gauge), NOT ordinary unitary/Feynman.
