## Slice
I own polarization syntax: the `{…}` markers on particle names, the spin-gated letter→helicity mapping in `extract_process`, the multiparticle-mixed-spin rejection, and `check_polarization` (ambiguous polarised/unpolarised mix detection + abort prompt). Out of slice: how polarized amplitudes/helicity sums are computed (HELAS/amplitude, numerical), MadSpin decay polarization, other process-syntax features (filters, coupling orders, chain decay, NLO brackets, tagged `!a!`).

## Core operating principles
- Source is truth for THIS input: adopt a scope-matching cached page (verify one file:line), else walk source. Pretrained recall is hypothesis.
- Spin is **2s+1 convention**: spin==1 scalar, 2 fermion, 3 vector(spin-1), 5 spin-2. All the exotic letters (T/A/G/H/Q/W/S) are spin==3-only.
- `L` on spin-1 = left-handed (-1), NOT longitudinal — warns but parses; longitudinal needs `0`. Common user trap.
- check_polarization is per-PID helicity-value-overlap, not a blanket polarized+unpolarized ban; different PIDs never conflict.
- FIVE ordered parse/construction gates (see pol-validation-pipeline): 1 placement (check_process_format) → 2 parse-entry (name/multiparticle-spin) → 3 letter→helicity → 4 whitelist backstop (PhysicsObjectError, currently unreachable) → 5 ambiguous-mix (check_polarization). A spec dies at the FIRST gate offended; exception type/text locates the gate. Placement fires before any letter is read.
- Runtime predictions (warning text, abort behavior) need a probe before being stated as fact; parse-time probes are cheap (`generate` only, no output/launch).
- Two-section return; obey output-concision; reject unmarked out-of-slice claims.

## Recent lessons (FIFO, max 5)
- pol-massgate-keys-on-attr: the NLO-pol massive gate (check_process_format) tests mass *attribute string* != 'ZERO', not numeric value. In restrict_default sm, light fermions (mu/e/ve) carry mass='ZERO' so pass; W/Z/t/b carry symbolic non-ZERO and are gated. Trigger: any "is this polarized leg allowed under noborn" question — answer depends on model restriction, not physics mass. Probe the attr.
- pol-symmetry-factor-is-the-warning-mechanism: the check_polarization "symmetry factor" warning is concrete, not vague — identical_particle_factor keys identical legs on (id, tuple(polarization)), so polarized+unpolarized copies of one PID get distinct keys → no 1/n!. Trigger: any "why is Z{T} Z rejected / why symmetry-factor issue" question — point to pol-symmetry-factor, don't restate the warning as opaque. Also: `2Z{T}` expands to two identical-pol legs (parses clean, factor applied); glued `Z{T}Z` dies at the rest-after-brace gate (2), not ambiguous-mix (5).
- pol-doc-label-table-traps: three oversimplifications a hand-authored {…} label table commonly makes (all corrected in pol-letter-mapping/pol-internal-and-help). (1) `{L}`/`{R}` are NOT fermion-only — source (5120-5125) branches on "any spin"; on a vector `L`=left −1 (with warning), `R`=right +1. Real spin partition: L/R universal, T/A/G/H/Q/W/S vector-only, 0 boson-only. (2) "external-only / can't polarize intermediates" is wrong for decay-chain HEADS (`t{L} > w+ b` parses); only the required s-channel `> Z{T} >` is rejected (placement gate), and the "ME sums over intermediate pols" rationale is helas-amplitude's, not mine. (3) `me_frame` IS the run_card param name (769-770) but its DEFAULT/"partonic-COM" semantics is run_card slice, not parse-side. Version claims (e.g. "since v2.7.0") are UNGROUNDED in this source tree — don't cache.
- pol-spinup-value-is-nhel-not-9: any "what SPINUP (LHE col 13) value does my polarized process write / does MG default SPINUP=9" question — the LO/NLO madevent writer writes the DEFINITE per-event helicity nhel (unwgt.f:609, write_event.f:262/368), NOT a blanket 9 (that =9 is only the NLO re-read utility analysis_lhe.f:182). Value = raw HELAS helicity int, so SPINUP=0 on a VECTOR = longitudinal (what {0} selects), NOT "averaged/no info" — canonical misread. My in-slice part: letter→SPINUP ({0}→0 massive-only, {T}→±1, {L}→-1 left-trap, {R}→+1). Writing/selection = output/mc-integration; route there for the field mechanics.
- pol-sole0-massless-drops-silently: a massless boson (mass attr=='ZERO': a, g) whose ONLY requested pol is `{0}` parses clean (logger.info), then at diagram_generation.py:1751-1755/1791-1796 the `0` is stripped → empty list → that id-combo is `continue`-skipped → if all combos go, `NoDiagramException: No amplitudes generated` (base_objects→diagram_generation 1911). NOT a polarization error; the text names no polarization. Probe-confirmed v3.7.1 (`a{0} z`→NoDiagram, `a{0R} z`→survives as `a{R} z`). Trigger: any "my polarized photon/gluon process generates no diagrams / NoDiagramException with a {0} leg" — diagnose as the sole-0 massless strip, not a broken process; tell user to add a real pol or drop the `{0}`. Massive boson keeps its `0` (Z{0} fine).
