- sm-auto-upgrades-at-nlo-not-error: `import model sm` for an NLO `[QCD]` process does NOT error ("Cannot find the model" is a MYTH). validate_model (loop_interface.py:297, docstring "Upgrade the model sm to loop_sm if needed"; called at amcatnlo do_add:513) TRANSPARENTLY re-imports: sm+[QCD]→`import model loop_sm` (add_on='', 347/352); sm+[QED]/[QCD,QED]→loop_qcd_qed_sm + force Feynman gauge (333-341). Trigger: any "NLO requires import model loop_sm / sm gives cannot-find error" claim — sm auto-upgrades silently; loop-model REQUIREMENTS (R2+UV) are nlo-model's slice, the do_add:513 gate + upgrade outcome + error wording are mine. See proc-validity-nlo-revalidation-hook claim-1 section.
- lo-vs-nlo-launch-dialogue-are-different-classes: an NLO output's `launch` enters `AskRunNLO` (amcatnlo_run_interface.py:922/924, 6 switches: order/fixed_order/shower/madspin/reweight/madanalysis) via aMCatNLOCmd.do_launch:1739→ask_run_configuration:1764. A LO output enters a DIFFERENT class `AskRun` (madevent_interface.py:497/500, 5 switches: shower/detector/analysis/madspin/reweight). NLO ADDS order+fixed_order, DROPS standalone detector. fixed_order=ON→shower-forbidden (consistency_fixed_order_shower:1150) has NO LO analogue. Trigger: any "the launch menu asks X" / LO-doc-applied-to-NLO claim — the two dialogues are not the same menu; cite the right class. See askrunnlo-dialog-and-showers LO-vs-NLO section.
- fxfx-stage-disambiguation: an FxFx (ickkw=3) question must be answered at the right lifecycle stage — the SAME condition (ickkw=3 + non-PYTHIA8) produces different effects at card-validate (silent repair), launch (reject/warn/y-n), event-gen (warn), shower (Exception). Don't cite one stage for another's timing. See fxfx-ickkw3-lifecycle.
- req_acc-vs-req_acc_FO: two similarly-named run_card params. FO loop binds req_acc=run_card['req_acc_FO'] (run():1955); req_acc_fo's default is POSITIVE (read at banner.py:5621) → DEFAULT FO run is ADAPTIVE, not fixed 2-pass. The NEGATIVE fixed-2-pass default belongs to the EVENT-mode req_acc (banner.py:5616), wrong-applied to FO. Trigger: any "default FO accuracy" claim — name which param and read its OWN default at its OWN line, don't carry -1 across.
