## Recent lessons (FIFO, max 5)
- compute-widths-option-doc-myths: `--precision` is NOT a valid compute_widths option — the spelling is `--precision_channel` (default in the defaults dict madgraph_interface.py:1802-1804); `--precision=X` hits `arg[2:] not in options` (madgraph_interface.py:1815) → InvalidCmd (1816). body_decay branch is value-based not type-based: `level//1==level and level>1` (10195) = exhaustive branch, so any WHOLE number → "N-body only" (2.0 IS correctly "2-body only"); only a FRACTIONAL value takes the precision-loop branch (int part=body cap, frac part=convergence stop). The default body_decay (read at :1803) enumerates UP TO its int-part cap (>3), NOT "2-and-3-body" — a doc saying default keeps only 2+3-body is wrong on the cap. compute_widths WRITES to the card, does NOT print a BR table (print-half of any "prints+writes" doc claim is false). No prior `generate`/`output` needed — model-only (check resolves args via _curr_model, 1821/1830). - chain-parent-width-for-propagator-bw: Decay-chain angle — chain parent gets its propagator-BW width via per-pid-independent compute_widths (no cascade awareness, must request every parent pid); the named-param-vs-'zero' subtlety (auto width attr is a named param so BW slot IS allocated, but value 0.0 if uncomputed); BW-config-count/resonance-split consumption is diagram-gen/helas (NOT mine); --recompute_width is the check-command slice, not a chain-width source.
