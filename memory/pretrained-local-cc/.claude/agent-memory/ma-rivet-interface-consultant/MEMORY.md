## Core operating principles
- Verify against source for THIS input every dispatch; in default mode a scope-matching cached page counts (sanity-check one cite). Pretrained MadGraph recall is only a hypothesis.
- Source = code + config files MG reads (rivet_card.dat, run_card, pythia8_card, mg5_configuration.txt). A config-content claim is a source claim — read the file.
- Never cache a runtime prediction (warning text, crash, sigma) as fact from reading alone; mark HYPOTHESIS until probed.
- Judge only inside the slice. Marked premise -> assume true; unmarked out-of-slice claim -> reject in its own section; question needing other territory -> state what I can establish, name the boundary.
- Two-section return (Source-walked facts / Implications); implications labelled DIRECT/INFERRED/HYPOTHESIS. Be concise (ma-output-concision).

## Recent lessons (FIFO, max 5)
- def-start-cite-drift: a function's cited def-RANGE start can drift while the interior cites (token line, branch line) stay correct — do_rivet-flow cited detect_card_type as 1192-1275 but the def opens at 1168 (interior 1226/1274-1275 were right). Also caught a function-range overrun (consistency_analysis_shower cited 794-808 but it ends at 804; 807 is set_default_analysis). Trigger: any wiki cite of a `def NAME (...lo-hi)` range. Correct behaviour: resolve the def-OPEN line independently, don't trust it because the interior cites resolve.
- enumeration-drift: distinct from cite-drift — citations can be CORRECT (file:line resolves) while the QUOTED LIST is stale. Found install-and-config's _advanced_install_opts missing 4 entries (cudacpp/hepmc3/pythia8_hepmc3/DMTCP), with_fastjet bare-flag wrongly attributed to rivet (MA5-only at 6227-6228), HEPTools dir listing short by 3. Trigger: any wiki line that enumerates a source list/set/dict. Correct behaviour: re-read the WHOLE enumeration block, not just confirm one member resolves.
- interior-cite-off-by-adjacent-line: the set-rivet-card-editor page got every SUBSTANCE claim right (single-token grab, immediate write, cross-card MPI-off, non-fatal try/except) but several interior cites landed on the ADJACENT line — single-token grab cited 6332 (real 6336; 6332 is the `if args[start+1]=='default'` test one branch above), Rivet-block range 6324-6336 (real ...6339), default-copy 6027 (real 6026), early gate 6004-6008 (real 6000-6004), PY8 guard 6304-6305 (real 6305-6306). Distinct from prior cite-drift (wrong file) and consequence-one-line-short (wrong logic): here the file is right and the logic is right, but the line points at the structurally-adjacent statement (the `if`-test instead of the `else`-assignment, the block-open instead of the value-grab). Trigger: authoring a code block where claim-line and cite-line differ by 1-4. Correct behaviour: cite the EXACT statement the claim is about (the `else:` assignment, not the `if`-test above it), and resolve the assignment line independently from the block-open line. A related instance has drift +4 (not 1-2) inside a SYMMETRIC two-branch method — postprocess-and-contur's setRelevantParamCard cited the x/y label-blank assignment as 1730-1731,1742 (real 1726 x / 1737 y) and the no-relvar fallback as 1732-1733 (real 1729-1730 x / 1740-1741 y); substance was right, lines shifted ~4. Sharpened trigger: methods with parallel x/y (or N-fold) branches where the same shape repeats — cite each branch's OWN line, don't carry the x-branch offset onto the y-branch.
- cite-drift-wrong-file: two stale cites — postprocess-return triple said 2080-2082 (real 3080-3082) and upgrade_tag was attributed to madgraph_interface.py (real madevent_interface.py:6387-6396, copy-pasted from the adjacent install block). Trigger: any cite landing in a plausible-but-wrong file/line. Correct behaviour: resolve EVERY cite to file+line, not just spot-check one.
- consequence-one-line-short: analysis-list-parsing predicted empty `analysis=[]` -> "rivet wrapper gets `-a ` with no analysis" (benign), hedged as an unprobed runtime claim. WRONG: the crash is pure source control flow, NOT a runtime claim — empty analysis_list makes `run_analysis=""`, then `"".split(",",1)[1]` at common_run_interface.py:2985 raises IndexError BEFORE any wrapper/env/HepMC. The page predicted a downstream consequence one branch SHORT of where control flow actually goes, and mis-labelled a walkable-from-source crash as needing-a-probe. Trigger: any page asserting "then X happens benignly" about a config edge case. Correct behaviour: walk the control flow to the NEXT statement that consumes the degenerate value (a `[N]`, `.index`, division, dict-key) — a degenerate input usually crashes there, and that crash is source-walkable, not a runtime hedge.
