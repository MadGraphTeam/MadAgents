## Slice
I own MadGraph's own install/build/plugin-install machinery: `do_install` (+ install update, install looptools), the install-target sets, source-server selection (`--source`), `convert_model` (py2->py3 UFO), HEPToolsInstaller/advanced_install, vendor tarballs, version files, and `mg5_configuration.txt` tool-path entries.
Out of slice: running/internals of installed tools (downstream slices), MG5 CLI/stage behavior (interface/stage slices), runtime reduction-library *selection* CutTools-vs-Ninja (madloop), model/restriction handling (model/ufo slices).

## Core operating principles
- Verify against source under `$MADGRAPH_INSTALL` for THIS input; adopt a scope-matching cached page per ma-wiki-as-evidence (sanity-check one cited file:line), else walk source.
- Target sets, version strings, config entries DRIFT across versions — always read them live, never recall.
- Server "uiuc" label is historical = INFN Milan mirror; don't assume a uiuc.edu host.
- Plugin version bounds are enforced at LOAD (misc.is_plugin_supported), not at install. __debug__ is False by default in a release run (auto -O relaunch) — a slice-wide switch: take the False branch of every install __debug__ gate by default (see debug-flag-release-behavior).
- Runtime predictions (warnings, install success, conversion success) are hypotheses until probed; mark them so.

## Recent lessons (FIFO, max 5)
- makeopts-fpe-trap-myth: Doc "MG5 ships strict `-ffpe-trap` in make_opts; fix=remove it" is BACKWARDS. In ALL shipped make_opts the ffpe-trap line is COMMENTED: LO `Template/LO/Source/make_opts:16-17`+`.make_opts:16-17` (active `FFLAGS= -w -fPIC`, `-w` SUPPRESSES warnings; ffpe line 17 commented); NLO `make_opts.inc:11-13` (active `FFLAGS=-O` line 12; ffpe line 13 + `-O -w` line 11 both commented). Stock build traps NOTHING — a SIGFPE from a default build is NOT MG5's flags. Doc fix only applies if a USER/overlay uncommented it, or env-set `FFLAGS` (which REPLACES default via `ifeq origin FFLAGS undefined` guard LO:15/NLO:10). Compiler config keys `fortran_compiler`/`cpp_compiler`/`f2py_compiler_py2/py3` (mg5_configuration.txt:38-46, all None) write to make_opts HEADER (`DEFAULT_F_COMPILER`/`DEFAULT_CPP_COMPILER`, above `#end_of_make_opts_variables`) via export_v4.py:2398-2456 + misc.py:639-642 — NOT into FFLAGS; propagates same compiler to all process-dir copies ("recompile all with same compiler" basis). CutTools+IREGI = bundled vendor/ source trees; ninja/collier/oneloop = advanced_install (vendor ships tarballs for offline). CAUTION: this image's NLO make_opts.inc is OVERLAY-PATCHED (`-mcmodel=medium` :63/:77, `-Wl,--no-relax` :77 for CutTools libcts.a) — NOT stock; read live. Cached to build-flags-and-make-opts.
- reduction-lib-doc-myths: (1) `install loop_qcd_qed_sm` is NOT a valid command — no model is in `_install_opts`/`_advanced_install_opts`; token check :1358 errors `Not recognize program`. loop_qcd_qed_sm is NOT bundled (only loop_sm under models/); EW loop model arrives via `import model loop_qcd_qed_sm`->online model-DB. (2) golem config-key default is `None` (UNCOMMENTED/active :222), NOT `auto` as commonly assumed; pjfry=auto, samurai/ninja/collier lines all COMMENTED (ninja/collier=./HEPTools/lib). (3) Install tokens case-sensitive exact-membership (no .lower()): `Golem95` (built-in) valid but `golem`/`golem95` error; `collier`/`ninja`/`oneloop` (advanced) valid but capitalized forms error. Cached to reduction-lib-tokens-and-config-keys.
- delphes-install-root-gate: doc "install Delphes downloads+compiles Delphes" is CORRECT (token `Delphes` EXACT, capital D, in `_install_opts`=built-in :3002; lowercase `delphes` errors InvalidCmd). BUT Delphes has a hard pre-download gate `check_install:1363`: needs `misc.which('root')` AND `ROOTSYS` env set (shared with ExRootAnalysis/Delphes2) else InvalidCmd, no download. Built-in path (NOT HEPToolsInstaller): `Delphes`->remap `Delphes3`:6620 -> wget(path['Delphes3'] from us-server manifest, not vendor/) -> tar -> make in place -> Makefile lib-edit :6769 -> copy delphes_card_CMS/ATLAS.tcl into Template/Common/Cards :6956 -> delphes_path=./Delphes. Lands at $MG5DIR/Delphes (NOT HEPTools/). Post-compile PY8 warning :6969 non-fatal. Cached to install-tree-and-target-dirs.
- debug-log-level-half: `--debug` does TWO things, not one. Beyond keeping `__debug__` True (branch-flip), `bin/mg5_aMC:143-144` bumps log level INFO->DEBUG, which un-hides every `logger.debug` install diagnostic (env-var advisory `:6440-6480`, "no model online" trace). PROBE-CONFIRMED: default run shows no `DEBUG:` lines/no debug banner; `--debug` shows both. So `misc.sprint` traces (silenced by `not __debug__`) AND `logger.debug` advisories (hidden at INFO) share ONE switch — `--debug`. Lesson: "I never saw message X" install Qs resolve via `--debug`; the sentinel-reset (set_configuration) is the lone exception (no log call at any level).
- verify-vendor-tarball-contents: RULE — a vendor tarball's filename is not evidence of its contents; `tar -tzf`/`md5sum` before claiming what an offline install of that tool reads. Grounding example (this image, probe-confirmed): `vendor/SMWidth.tar.gz` is byte-identical to `vendor/ninja.tar.gz` and unpacks to ninja source, NOT SMWidth — an offline SMWidth install would silently get ninja. Re-verify live; the identity is an image artifact, not a standing fact.
