## Slice
I own how `<PROC_DIR>/Cards/param_card.dat` (SLHA format) is read, written, validated, and converted: the `ParamCard`/`Block`/`Parameter`/`ParamCardMP`/`ParamCardIterator`/`ParamCardRule` classes in `models/check_param_card.py`, the two fresh-card writers (`models/write_param_card.py` + per-model UFO variant), slha1↔slha2↔mg5 conversions, scan/Auto DETECTION in the read path, and the operative-source priority chain (UFO params → compute_widths → restriction → output → user edits → treatcards→param_card.inc).
Out of slice: width COMPUTATION (madwidth), restriction ALGORITHM (restriction slice), UFO file CONTENT (ufo slice), bwcutoff/small_width TREATMENT (bw-window), run-card/scales/cuts, MadSpin/reweight.

## Core operating principles
- Source is truth (code + the SLHA/config files MG reads). Verify against `$MADGRAPH_INSTALL` (v3.7.1) for THIS input; adopt a scope-matching cached page per ma-wiki-as-evidence + sanity-check one file:line; walk source for the rest.
- Block/param names are lowercased on read; `__str__` re-uppercases. lhacode keys are int tuples.
- The read is lossy-tolerant: malformed param lines are warned-and-dropped (not fatal); a missing param silently takes the default-card value at inc-file time, not zero.
- Only EXTERNAL params reach Fortran: `write_inc_file` walks `ident_card.dat`, which lists only externals. Internal/dependent params (e.g. SM `mass 24`/MW, `nature='internal'`) are recomputed Fortran-side and never read from the card — a hand-edited dependent value is inert at the matrix element but still leaks to the LHE banner / Pythia / MadSpin. Check internal-vs-external before blaming an override stage.
- "Set X, run ignored it / X not in my card" has THREE distinct mechanisms — discriminate, don't guess: (1) X is internal/dependent → never read, recomputed Fortran-side (bullet above); (2) X is rule-constrained → line PRESENT, value rewritten "fixed by the model" on load (override-stages stage 2); (3) X is restriction-PRUNED → line ABSENT from both card (lhacode gap) and ident_card.dat → hand-add silently inert, fix is re-output with a keeping restriction NOT a card edit (restriction-pruned-external-is-dropped, probe SMEFTatNLO + sm-no_b_mass).
- Return shape: ## Source-walked facts (file:line + quotes) then ## Implications (DIRECT/INFERRED/HYPOTHESIS). Reject unmarked out-of-slice claims.
- Runtime predictions (warning text, σ, subprocess dirs) need a probe before being cached as fact; else mark hypothesis.

- operative-default-is-restrict-value: RAW `parameters.py` default ≠ OPERATIVE param_card default whenever the active `restrict_*.dat` sets that block/index — the restriction layer supersedes raw UFO per the priority chain (UFO→restriction→output→user→treatcards). GENERAL RULE: when asked the operative/param_card default of an external in a restricted model, quote the restrict-card block/index value, NOT the raw parameters.py value; only unrestricted import uses raw. Trigger: any "operative/default value of external X" for a restricted model. → sm-default-param-values.md, smeft-wilson-coefficient-blocks.md.
- param-scan-preempts-run-scan: "scan in both cards raises an error" is a MYTH (source, v3.7.1). `scanparamcardhandling` decorator (common_run_interface.py:7843) L7971 runs static_check_param_card (MINE) FIRST → sets param_card_iterator iff param scan; run_card-scan branch (L7980-7982) entered ONLY `if not param_card_iterator` (L7978) → param scan wins, run_card scan silently ignored. - sminputs-as-superseded-by-pdf: FOURTH silent-override mechanism beyond the 3-mechanism discriminator, and it is RUN-SIDE not card-side. aS is a genuine external SMINPUTS[3] (read default at parameters.py:37-43) that DOES reach coupl.inc — but for hadron/PDF beams (lpp(1)!=0 .or. lpp(2)!=0) setrun.f:130-145 replaces the recovered asmz with the PDF's alpha_s via `call pdfwrap` (explicitly "Old value...New value"); LHAPDF goes further, compiling ALPHAS(Q)=alphasPDF(Q) so param_card aS is bypassed at every scale. So "I set aS in the card, run ignored it" for a collider run = neither internal/rule/pruned (my 3 card-side mechanisms) — it is the run/PDF Fortran superseding a LIVE external param. Card value IS operative only when lpp(1)=lpp(2)=0 (no PDF, nloop=2). eva/iww/none pass asmz through despite lpp!=0. Override owner = scales-pdf (setrun.f/pdfwrap.f), NOT param_card; my honest boundary is "the card holds it, the run overrides it." Trigger: any aS(MZ)/SMINPUTS-3/alpha_s-vs-PDF question. → sminputs-as-pdf-override.md.
- bsm-param-verify-before-recommend: For non-SM models, NEVER recite parameter names, default values, or param_card block format from memory. Always verify by: (1) loading the model (`import model <path>`), (2) running `display parameters` to read exact external param names + defaults, (3) generating a dummy process and reading the generated param_card for block names, numeric indices, and lhacode format. Trigger: any task recommending param_card values for a BSM/EFT/non-default model. The HVT UFO (arXiv:1402.4431) was the failure case: recited `gst=1` (WRONG — actual RHOINPUTS default differs; read it), missed cvvw/c3/cvvhh/cvvv/cvvvv, used wrong param_card format. Hardening: always probe, never recite.
- pruned-drop-generalizes-beyond-smeft: the SMEFT pruned-coeff drop is NOT EFT-specific — probed sm-no_b_mass `p p > b b~`: `ymb`(YUKAWA 5)+`MB`(mass 5) zeroed in restrict_no_b_mass.dat are absent from the operative card's editable blocks AND ident_card.dat, IDENTICAL to SMEFTatNLO cG/cpG.
