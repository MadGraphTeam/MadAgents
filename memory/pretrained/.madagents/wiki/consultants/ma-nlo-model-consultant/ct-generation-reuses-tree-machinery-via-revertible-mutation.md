# CT generation reuses the tree machinery via revertible model/UFO mutation

(v3.7.1, `$MADGRAPH_INSTALL`.) Deeper principle uniting ct-diagram-gen-pass-mechanics,
ctparameter-eps-fin-expansion, and ct-vertex-consumers: MadGraph does NOT have a bespoke
counterterm walker. It generates CT diagrams and imports CT couplings by **temporarily
mutating shared model/UFO state so the ordinary tree-level machinery can be reused, then
reverting the mutation** so the model/UFO is left as it was. The same mutate→reuse→revert
bracket recurs at three sites, and (load-bearing) none of them is wrapped in try/finally —
a mid-bracket raise leaves shared state corrupted.

## The recurring shape
1. Stash the current state (or note it will be torn down).
2. Mutate the SHARED model or UFO object so a generic routine sees CT content it normally
   would not.
3. Run the ORDINARY routine (`generate_diagrams`, `add_CTinteraction`).
4. Revert the mutation, restoring the original state.

## Instance A — set_Born_CT: synthetic order + widened vertex dict (double-generate)
`$MADGRAPH_INSTALL/madgraph/loop/loop_diagram_generation.py` set_Born_CT (1207):
- Adds a synthetic coupling order `UVCT_SPECIAL` to the shared model
  (`order_hierarchy['UVCT_SPECIAL']=0` 1236, `coupling_orders.add('UVCT_SPECIAL')` 1237) and
  tags each selected UVtree interaction with `orders['UVCT_SPECIAL']=1` (1238-1241).
- Widens the model's vertex dict: `actualize_dictionaries(useUVCT=True)` (1244) — now
  `generate_ref_dict` includes the UVCT interactions (loop_base_objects.py:1468-1478).
- Sets `process['orders']['UVCT_SPECIAL']=1` (1248) and re-runs the ORDINARY tree generator
  `super(LoopAmplitude,self).generate_diagrams(True)` (1250-1251). Diagrams come back tagged
  `UVCT_SPECIAL==0` (Born) or `==1` (the counterterm diagrams); only the latter become
  LoopUVCTDiagrams (1253-1266).
- Tears down: `del` the synthetic order from process/order_hierarchy/coupling_orders/each
  interaction (1270-1275), `actualize_dictionaries(useUVCT=False)` to revert the dict (1277).
So UVtree factorizing CTs are generated by running the SAME machinery a second time with the
model temporarily widened, NOT by a CT-specific walker. (Detail: ct-diagram-gen-pass-mechanics.)

## Instance B — treat_couplings: rewritten coupling value, explicit "leave UFO intact"
`$MADGRAPH_INSTALL/models/import_ufo.py` treat_couplings (1383-1556):
- For a CT coupling whose value references a CTParameter, stashes `coupl.old_value =
  coupl.value` and replaces `coupl.value` with a per-pole dict (1548-1549). The source comment
  is explicit: "I will be reverted / right after the addCT_interaction() function so as to leave
  / the UFO intact, as it should." (1544-1546).
- `add_CTinteraction` consumes the dict form.
- `revert_CTCoupling_modifications` (2100-2113) restores: `for coupl in
  self.model.all_couplings: if hasattr(coupl,'old_value'): coupl.value = coupl.old_value;
  del(coupl.old_value)`. The dict form exists ONLY between treat_couplings and the revert.
(Detail: ctparameter-eps-fin-expansion.)

## Instance C — the dict toggle itself
`actualize_dictionaries(useUVCT)` (loop_base_objects.py:1468-1478) is the reusable mutation
primitive both directions of instance A call: `True` rebuilds `ref_dict_to0/to1` with the
UVCT interactions included, `False` reverts to the no-CT default. The model's vertex lookup
dict is the shared state being flipped.

## The consequence the instance pages don't each state
A reader debugging "why does the model look unchanged after a CT import" or "why does loop
CT-gen reuse the Born generator" or "why is the model dict left widened after a failed
generation" is hitting ONE design: revertible mutation of shared state. The pattern predicts:
- The UFO/model is restored to its original strings, but the treat_couplings revert is
  **conditional on the full pass completing**, not automatic: the source comment says the
  value-substitution "will be reverted in OrganizeModelExpression only, so that the main()
  function of this class *must* be run on the UFO to have this change reverted" (592-594). So a
  second pass over the same UFO sees the original strings ONLY if main() ran to completion the
  first time — an aborted pass leaves the dict-form values in place (this is the same
  exception-unsafety hazard, stated positively).
- **Exception-unsafety (the hazard):** the set_Born_CT bracket (1236-1277) has NO try/finally
  around it (verified: the only try in 1207-1320 is an unrelated try/except KeyError at the
  order-setting tail). If `generate_diagrams` raises mid-bracket, the shared model is left
  with `UVCT_SPECIAL` still in coupling_orders/order_hierarchy and the vertex dict still
  widened. Same shape for treat_couplings: a raise between the value-rewrite and
  `revert_CTCoupling_modifications` leaves CT couplings as dicts, not strings. Both are
  pointer-level hazards, not observed failures — but they explain a class of "stale model
  state after an aborted generation" symptoms.

## Boundary
- Static structural mechanism: predicts WHICH shared state is mutated/reverted and the
  exception-unsafety window, NOT runtime numerics (diagram counts / σ). Those need a probe.
- The per-vertex `is_*` SELECTION inside the widened pass is ct-vertex-consumers' territory;
  the `generate_ref_dict` exposure gate is ct-diagram-gen-pass-mechanics'; the per-pole dict
  CONTENT is ctparameter-eps-fin-expansion's. This page is only the unifying mutate→reuse→
  revert principle and its exception-unsafety, which none of them frames.
- Instance pages KEPT — they carry the per-site file:line specifics and worked examples this
  page indexes.
