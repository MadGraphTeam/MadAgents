# BSM/EFT param-card value → fate (the general mapping)

A restrict card IS a param_card (the bundled cards' header literally reads
`## PARAM_CARD AUTOMATICALY GENERATED BY MG5 ...`, e.g.
`models/2HDMtypeII/restrict_nobmass.dat:2`). Restriction reads the VALUE the card
gives each EXTERNAL parameter and maps it to a fate in the operative model. The
mechanism is model-agnostic: SMEFT Wilson coefficients, 2HDM Higgs-potential
quartics, and MSSM mixing-matrix entries all flow through the SAME `RestrictModel`
passes. The SMEFT page (smeft-restrict-operator-selection.md) states this for
Wilson coefficients only; THIS page is the general statement + the non-SMEFT
instances + the escape valve.

## The value→fate table (any external BSM/EFT param)
For an external param `p` (block, lhacode), the restrict-card value decides:

| card value of `p` | pass that fires | operative fate |
|---|---|---|
| `0` (and name≠'ZERO') | `detect_special_parameters` null list (2621) → `fix_parameter_values` (2980) | p → internal `0.0` (or removed if unused, `simplify=True`); every coupling that reduces to 0 → `detect_identical_couplings` zero (2422) → `remove_interactions` (2425) prunes/trims its vertices. Emits `rule_card.add_zero` (3010). **De-selection.** |
| `1` | `detect_special_parameters` one list (2623) | p → internal `1.0` (or removed if unused). Emits `rule_card.add_one` (3012). |
| nonzero, DISTINCT in its `(block,value)` group | none (not special, not identical) | p stays a free external coefficient the user sets later. **Selection.** |
| nonzero, EQUAL to another param in the SAME block | `detect_identical_parameters` (2709) `key=(lhablock,value)` (2728) → `merge_iden_parameters` (2825) | the two collapse to one free param; loser → internal `factor*kept` (2859), `rule_card.add_identical` (2844). User can no longer vary them independently. **Silent merge hazard.** |
| nonzero, EXACT NEGATIVE of another in the block | `detect_identical_parameters` `mkey=(lhablock,-value)` (2729, coeff −1) | merged with coeff −1; `rule_card.add_opposite` (2847). |

(Masses/widths get extra handling: a zero MASS → particle mass set `'ZERO'` 2987-3001; DECAY block is categorically exempt from identical-merge, 2726 — see autowidth-restore.md. Mass/width MERGE also repoints the particle field, 2864-2874.)

The full prune mechanics are in remove-interactions.md / detect-identical-couplings.md;
the param-fixing/merging line detail in parameter-fixing-and-merging.md; the rule-write
side in rule-write-target-asymmetry.md. This page is the user-facing value→fate digest.

## Three concrete BSM/EFT families (source-verified v3.7.1)

### 1. SMEFT Wilson coefficients (EFT) — direct coupling drive
`models/SMEFTatNLO/restrict_*.dat`. Each dim-6 coefficient (blocks DIM6/DIM62F/DIM64F/
DIM64F2L/DIM64F4L) is a direct external param. `0` de-selects the operator; a distinct
nonzero fraction selects + de-duplicates it. `restrict_default.dat` zeroes ALL → pure-SM
operative model. Detail + per-card operator sets: smeft-restrict-operator-selection.md.

### 2. 2HDM Higgs-potential param (non-SMEFT BSM) — INDIRECT chain
`models/2HDMtypeII/restrict_nobmass.dat:23` sets `higgs 3 = 0.` i.e. `lR7=0` (the card
block is written lowercase `Block higgs`, line 20; LHA block names are case-insensitive so
it binds the UFO's `lhablock='Higgs'` param). `lR7` is external (`parameters.py:45-51`,
`lhablock='Higgs' lhacode=[3]`, `value=0`). It does NOT appear in `couplings.py` directly
(grep: 0 hits) — it feeds an INTERNAL param `l7` (`parameters.py:271-275`, `value='lR7'`,
complex), which 34 couplings.py expressions use. So the de-selection chain for a non-SMEFT
BSM potential param is one hop longer than the SMEFT direct case:
**external `lR7`=0 → `detect_special_parameters` null list (lR7 is the zero param, not l7) →
`fix_parameter_values` `simplify=True` scan finds `lR7` STILL USED (it appears inside the
internal `l7`'s expr `'lR7'`; the param-expr scan is at 3070-3072, alongside the coupling
scan 3030-3034 / lorentz-formfactor scan 3037-3041) → `lR7` rebuilt as `0.0` internal (3086).
`l7` is NEVER itself rewritten — it stays internal with `value='lR7'` and simply EVALUATES to
0; every coupling carrying `l7` then evaluates 0 → `detect_identical_couplings` zero →
`remove_interactions` prune.** Same fate, indirect path. (Key correction vs the naive read:
it is `lR7`, the zero EXTERNAL special param, that fix_parameter_values rebuilds as `0.0`
internal; `l7` is an ordinary internal param that is left alone and inherits 0 by reference.)
The same card zeroes `MASS 5` (MB) and `yukawa 5` (ymb) — the "no b mass" content — both
external→`0.0`/`'ZERO'`. This is the BSM analogue of zeroing a Wilson coefficient: a BSM
Lagrangian parameter, not a "physics input," chosen at load time to switch a term off.

### 3. MSSM / SLHA2 mixing — values 0 and 1 are STRUCTURAL, not de-selectors
`models/MSSM_SLHA2/restrict_default.dat` is a large SLHA2 card. Its mixing blocks carry many
literal `1.000000e+00` and `0.` entries — e.g. `Block USQMIX` (block at line 8, rows 9-16):
the lhacodes are TWO-index `(i,j)` matrix positions, with `RRu11=(1,1)=1, RRu22=(2,2)=1,
RRu44=(4,4)=1, RRu55=(5,5)=1` (diagonal) and off-diagonal mixings `RRu33/RRu36/RRu63/RRu66`
nonzero (read magnitudes in the active card). These 0/1 values would normally be de-selected by `detect_special_parameters`,
which is why MSSM_SLHA2 is forced `keep_external=True`.

**Branch detail (v3.7.1):** MSSM_SLHA2 reaches `keep_external=True` via the
EXPLICIT name-match `elif model_name == 'MSSM_SLHA2'` at **import_ufo.py:302-303** — NOT the
`mssm` branch (298-299) and NOT the SLHA2-block-signature `elif` at 300 (that test requires
block `'SL2'` in the model's external blocks, but this card declares `MSL2`, not `SL2`, so the
signature `all(...)` is False here). The `name=='mssm' and not keep_external → raise Exception`
guard at **2398 does NOT fire for MSSM_SLHA2**: the guard checks `self.get('name')`, which is
the model directory basename (`import_ufo.py:412`), i.e. `MSSM_SLHA2`, not the literal `mssm`.
The 2398 raise is a safety guard specific to the v4-style model named `mssm`; what protects
MSSM_SLHA2's structure is the keep_external flag set at 302-303, not that raise.

Under `keep_external`, the first (non-keeping) identical-merge pass is skipped (`if not
keep_external` at 2445) and merged non-mass/width externals keep their card row (name blanked)
instead of being deleted (2851-2857; the else at 2855-2857 blanks `obj.name`). So an SLHA2
user's card stays structurally intact even though the operative model treats the 0/1 mixings as
internal. Detail: restrict-flag-determination.md. **Caution: for MSSM the 0/1 in the card are
mixing-matrix structure, NOT "turn this operator off" — do not read them as de-selection.**

## The magic-value escape — keep a param effectively 0 or 1 WITHOUT restriction touching it
Restriction offers two sentinel values a card author uses to set a parameter to ~0 or ~1
while DODGING the special/identical passes:
- `9.999999e-1` — survives every pass, then un-escaped to literal `1` in `parameter_dict`.
- `0.000001e-99` — survives every pass, then un-escaped to literal `0`.

Mechanism (import_ufo.py:2455-2462), runs AFTER all fix/merge passes:
```
for name, value in self['parameter_dict'].items():
    if value == 9.999999e-1:   self['parameter_dict'][name] = 1
    elif value == 0.000001e-99: self['parameter_dict'][name] = 0
```
Why they survive: `detect_special_parameters` tests `==0`/`==1` EXACTLY (2621-2624), and
`detect_identical_parameters` explicitly skips `value in [0,1,0.000001e-99,9.999999e-1]`
(2724). So a param set to `0.000001e-99` is NEVER flagged null, NEVER converted
external→internal, NEVER pruned, NEVER merged — it stays a free external param — yet its
NUMERIC value used everywhere downstream is exactly 0 (after the un-escape). This is the
param-setup tool for "I want this BSM coupling at zero numerically but I still want to keep
the param external/free so the user (or a later card) can turn it on." Emits NO rule_card
entry (it never hit add_zero/add_one; the escape loop touches only `parameter_dict`).

NO bundled restrict card currently uses either escape — `grep -lE '0\.000001e-99|9\.999999e-1'
models/*/restrict_*.dat` returns NONE (v3.7.1). It is a mechanism
available to a USER-authored restrict card, not exercised by any shipped BSM/EFT card.
(See sm-restrict-files.md for the SM-side note of these constants.)

### Doc-folklore debunk: the escape literals are EXACT, and near-zero is a hazard not a shield
A circulating SMEFT how-to claims you can "keep a Wilson coefficient safe from restriction"
by setting it near-1 as `9.999e-01` or near-zero as `1e-99`. **Both specific values are wrong.**
The comparisons at import_ufo.py:2458-2461 and the skip-list at 2724 are EXACT float equality
against exactly `9.999999e-1` (seven 9s) and `0.000001e-99` (=1e-105) — no tolerance band. So:
- `9.999e-01` = 0.9999 ≠ `9.999999e-1`. It is NOT the escape. It merely behaves as an ordinary
  distinct-nonzero placeholder: nonzero so the vertex survives, ≈1 but numerically 0.9999 (not
  un-escaped to 1). It "works" for keeping an operator ON — but by the plain distinct-nonzero
  rule, not by any magic. It is NOT skipped by 2724, so it CAN collide/merge with another 0.9999.
- `1e-99` ≠ `0.000001e-99`. For the PARAMETER it dodges the `==0` null test (2621) so it stays
  external — but that is the trap: any coupling built from a WC that tiny evaluates below the
  `abs<1e-13` zero-band in `detect_identical_couplings` (2552, or the `<1e-10` strict re-run
  2557) → those couplings are flagged zero → `remove_interactions` PRUNES the operator's
  vertices. So `1e-99` is the OPPOSITE of safe: param stays "on" in the card, operator vertices
  silently gone. (INFERRED — coupling magnitude tracking the WC is the generic linear case;
  a coupling with a large prefactor could stay above 1e-13. Probe `display interactions` to
  confirm for a specific operator.) The grounded lesson: use the EXACT `0.000001e-99` if you
  truly want the escape, and never rely on a "small enough ≈ safe" intuition — the zero-band
  is at the COUPLING level, not the parameter level.

### 0 and 1 do NOT merge with each other (precision on the "same value → merge" claim)
The "same value → merge" hazard (table row 3) fires only for a shared value OUTSIDE
`{0, 1, 0.000001e-99, 9.999999e-1}` — a generic shared nonzero like two coeffs both = 0.5.
Two coeffs both = 0 each go to the null list (2621) → each becomes internal `0.0` independently;
two coeffs both = 1 each go to the one list (2623) → each becomes internal `1.0` independently.
Neither pair MERGES, because `detect_identical_parameters` `continue`s on value in
`[0,1,0.000001e-99,9.999999e-1]` (2724). So a doc that says "setting active WCs to the same
value OR to 1.0 both cause a merge" conflates two distinct fates: generic-shared-value → MERGE
(operators become non-independent, add_identical rule); value 1.0 → external→internal
CONVERSION (the coefficient is FIXED at 1.0 and drops out as a free card line — a different
hazard, and it is per-coefficient, not a merge between them).

## Gaps (runtime, not settle-able from source alone)
- Which EXACT params a given model's restrict card touches needs reading THAT card — this
  page lists three families, not an exhaustive per-model map. Read the card.
- Whether a zeroed coefficient actually removes a vertex vs only trims it depends on whether
  another surviving coupling shares the vertex — a runtime/`display interactions` question
  (probe: `import model <m>-<restr>` then inspect surviving interactions).
- A USER-edited process-dir param_card setting two same-block coeffs equal does NOT re-merge
  them — merging is load-time-only against the SHIPPED card; the user card is validated
  against the accumulated rule_card, never re-restricted (smeft page Gaps).
