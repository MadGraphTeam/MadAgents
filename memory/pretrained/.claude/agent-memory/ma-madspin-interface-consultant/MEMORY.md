## Slice
I own the MadGraph<->MadSpin interface: how MadGraph invokes MadSpin (launch -M, do_decay_events), the cards MadGraph produces, the banner handoff format, MadSpinOptions and the MadGraph-side params affecting MadSpin behaviour. OUT of slice: MadSpin internal decay.py (BW sampling, polarization-preservation, decay generation), bwcutoff registration (bw-window), chain-decay generate-line syntax (chain-decay slice), downstream tools, compute_widths (madwidth), NLO+MadSpin internals (amcatnlo).

## Core operating principles
- Source is truth for THIS input: walk source, or adopt a scope-matching cached page (sanity-check one file:line). Pretrained recall is hypothesis only.
- Options resolve in STAGES (see madspin-option-resolution-staging): banner-derived sentinels (BW_cut=-1, Nevents_for_max_weight=0, nb_sigma=0, frame_id) at do_import; but seed & input_format='auto' resolve at the LAUNCH target, and seed increments per-PDG during generation. options['X'] differs pre-import/post-import/post-launch.
- BW_cut: inherited value above the NWA-validity threshold (import interface_madspin.py:253) -> non-fatal logger.critical; above the hard-abort threshold (do_launch :653) -> hard Exception. Only the abort aborts; read both thresholds fresh at their lines.
- Runtime predictions (warning text, sigma, output filenames, error msgs) need a probe before being cached as fact; mark unprobed ones as hypothesis.
- Stay in slice: describe what the interface does; name the boundary and hand off decay.py internals.

## Recent lessons (FIFO, max 5)
- squared-order-rejection-is-inherited: a card `decay` line with `^2`/`NP^2==N` IS rejected, but do_decay (interface_madspin.py:420-437) does NOT check for `^2` — only WARNS on `=` (:431-432). The `^2` survives into the spliced decay-CHAIN generate line (get_proc_with_decay @decay.py:2869/2883) and trips the SHARED core guard madgraph_interface.py:3301-3304 "Decay processes cannot specify squared orders constraints" (predicate decays_have_squared_orders base_objects.py:3576). Contrast: a NON-chain `generate` line accepts `^2` (extract_process :3310, `^2` grammar :4927-4940) — rejection is chain-only, and MadSpin always fuses as a comma-chain. Default append is QCD=99 (amplitude order, :2857), never squared → default path safe. Trigger: "does MadSpin reject/accept <coupling-order syntax>?" -> the interface RELAYS to the shared chain parser; find the guard in madgraph_interface.py, not interface_madspin.py. See madspin-decay-chain-grammar.
- full-not-madspin-alias: doc claimed spinmode 'full' is an alias for 'madspin' (functionally identical) -> WRONG. Same launch dispatch (both fall through none/onshell/bridge switch @:617-634) BUT diverge: (1) interface :474-476 rejects `set run_card` ONLY when spinmode=='madspin' -> 'full' PERMITS run_card cuts on the decay ME, 'madspin' forbids; (2) decay.py has explicit mode=='full' branches (:3506,:4142) — internals. onshell REQUIRES f2py: run_onshell weight imports all_matrix2py (:1770), smatrixhel@:1799. Trigger: "X is an alias for Y" -> grep for `== 'X'` distinct branches before believing it.
- gen-all-me-three-copies: dead-code claim cited bare `:1803`/`:1816`/`:1844` -> resolved into the WRONG FILE (page is about decay.py, but the dead method is in interface_madspin.py). There are THREE `generate_all_matrix_element`: decay.py:2741 (LIVE base, QCD=99@:2857) + decay.py:4201 (LIVE onshell override, QCD=99@:4280, NOT dead) + interface_madspin.py:1803 (DEAD, raise@:1844). Trigger: a page documenting one file cites a method that lives in another -> ALWAYS carry the FILE with the line number; bare `:N` silently lands in the page's primary file.
- bw-cut-location: my card said BW_cut=-1 resolves in do_launch; source says it resolves in do_import (:251). Trust source over card text; the >100 abort is the only launch-side BW_cut check.
- nlo-two-fixed-orders: the doc's "MadSpin at NLO uses fixed_order for counter-events" conflates TWO same-named knobs. (1) aMC@NLO launch SWITCH fixed_order (amcatnlo:925) = fNLO computation, no events — amcatnlo slice, NOT a MadSpin option. (2) MadSpin CARD option fixed_order (interface_madspin.py:72, default False) = read LHE as event GROUPS (event[0] representative, :1410-1418). Card fixed_order is ONSHELL-ONLY: every branch is in run_onshell(:1373-1577)/get_maxwgt_for_onshell — none in run_bridge/full-madspin (warning :125-126 literally true). NLO madspin gate = {OFF,ON,onshell} (amcatnlo:1324); QED splitting_types -> OFF only (:1321); ninitial==1 removes MadSpin; ON->spinmode madspin NOT onshell (:1367); frame_id forced 6 at NLO (do_import:260). By default NLO card has fixed_order=False (do_decay_events doesn't set it). Trigger: any "fixed_order at NLO" claim -> ask WHICH file's fixed_order.
